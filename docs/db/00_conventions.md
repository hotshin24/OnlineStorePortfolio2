## 2. Oracle 문법 기준 [확정]

- 21c 기능까지 사용한다 (네이티브 `JSON` 타입 등). 19c 이식성은 보장하지 않는다 (2번).
- SQL `BOOLEAN`이 없으므로 Y/N 값은 `CHAR(1)` + `CHECK (X IN ('Y','N'))`로 처리한다.
- Oracle CHECK는 조건 결과가 UNKNOWN이면 통과한다. NULL 허용 컬럼을 `=`, `⇔`, `IN`으로 비교하는 CHECK는 NULL일 때 막는지 통과시키는지를 문장에 적는다 (예: "(NULL 포함)", "수단이 NULL이면 막는다"). 일괄 `NVL`은 쓰지 않는다. 뜻이 바뀌는 CHECK가 있기 때문이다. [확정, 2026-11-26 결제 컬럼 검토 PYC-80 A. 회원·상품·주문 CHECK는 각 도메인을 다시 열 때 점검]
- TDE 사용 가능 (`V$OPTION` 확인 완료).
- 문자셋, 스키마 이름은 미확정이다.

## 4. 키 전략 [확정]

- PK는 테이블별 SEQUENCE로 만든다. `INCREMENT BY 1`.
  - `CACHE`: 고빈도 거래 테이블 100, 저빈도 테이블 20. 대상 테이블은 각 도메인에서 확정한다.
- PK·FK 타입은 `NUMBER(19,0)`이다.
- 매핑 테이블: 단순 연결은 복합 PK, 참조되거나 이력·상태·차수가 있으면 대리 PK + 복합 UK.
- 대리 PK가 기본이고, 업무상 식별 가치가 있는 테이블에만 업무 키 UNIQUE를 둔다. 업무 키 형식·발번 방식은 각 도메인에서 정한다.
- 외부 분석 도구에는 `MEMBER_ID` 대신 회원 테이블의 분석용 무작위 식별자를 보낸다 (12-4).

## 5. 시스템 컬럼 [확정]

모든 테이블 끝에 둔다. 로그·원장 테이블도 포함한다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `CREATED_BY_TYPE_CD` | `VARCHAR2(20)` | 생성 행위자 유형 |
| `CREATED_BY` | `VARCHAR2(100)` | 생성 행위자 식별자 |
| `CREATED_AT` | `TIMESTAMP` | 생성 시각 |
| `UPDATED_BY_TYPE_CD` | `VARCHAR2(20)` | 수정 행위자 유형 |
| `UPDATED_BY` | `VARCHAR2(100)` | 수정 행위자 식별자 |
| `UPDATED_AT` | `TIMESTAMP` | 수정 시각 |

- 논리 삭제 테이블은 `DELETED_BY_TYPE_CD`, `DELETED_BY`, `DELETED_AT`을 추가한다.
- 행위자 유형: `MEMBER`, `ADMIN`, `SYSTEM`, `BATCH`, `EXTERNAL`, `GUEST`. 모든 테이블에 유형 CHECK를 건다.
- 식별자: 회원·관리자 ID, 처리 이름, 배치 작업명, 업체 코드(`EXTERNAL`), 비회원 주문번호(`GUEST`).
- 회원 가입은 시퀀스로 `MEMBER_ID`를 먼저 받아 본인 ID로 기록한다. 관리자 대리 작업은 실제 작업자를 기록한다.
- 값은 애플리케이션 공통 코드가 채운다. Oracle 스케줄러 배치는 PL/SQL에서 직접 채운다.

## 6. 삭제·이력 정책 [확정]

| 테이블 유형 | 처리 |
|---|---|
| 거래·원장·이력 | 삭제·수정하지 않는다. 반대 금액 행으로 정정한다. |
| 로그 | 보관 기간이 지나면 파티션 단위로 제거한다. |
| 상태가 있는 엔티티 (회원, 상품, 발주, 관리자) | 상태 코드로 처리한다. |
| 마스터·설정 | 논리 삭제 (`DELETED_*`). `USE_YN`(사용 중지)과 별도. |
| 회원 소유 목록·단순 매핑 (장바구니, 위시리스트, 배송지) | 물리 삭제한다. |

- 조회할 때 `DELETED_AT IS NULL`을 직접 쓴다. 공통 조회 조건과 삭제 행 자동 테스트로 누락을 막는다.
- 개인정보 없는 논리 삭제 행은 1년 뒤 물리 삭제한다. 재사용 금지 값은 지우기 전에 `SYS_RESERVED_KEY`로 옮긴다.
- 자식이 있는 부모는 삭제할 수 없고 `USE_YN`으로 사용 중지만 한다.
- UNIQUE: 재사용 금지 값(주문번호, 업무 코드 등)은 일반 UK. 이메일·휴대폰은 탈퇴 확정 시 HMAC 해시를 NULL로 바꾸고 일반 UNIQUE를 유지한다.
- 상태 이력: 대량 도메인(주문·클레임 후보)은 전용 이력 테이블, 나머지는 `SYS_STATUS_HIST`.
- 범용 테이블(`SYS_STATUS_HIST`, `SYS_PII_ARCHIVE`)은 대상별 FK 컬럼 + 정확히 하나만 채우는 CHECK로 참조한다.

## 7. 금액·통화 [확정]

- 원화 `_AMT`는 `NUMBER(15)`이다.
- 외화(생산·소싱만)는 `NUMBER(18,4)`에 통화 코드와 환율 컬럼을 함께 둔다.
- 할인 배분은 주문 상품 × 할인 출처 배분 테이블에 둔다 (15-5 B). 끝수 처리 규칙은 주문 도메인에서 정한다.

## 8. 코드값 관리 [확정]

- 정해진 값 중 하나를 고르는 컬럼은 값 목록(코드, 한글명, 영문명, 설명, 정렬)을 정의한다.
- 값은 `CMM_CODE_GROUP` / `CMM_CODE`(`ATTR1`~`ATTR5`)나 마스터 테이블에 담는다.
- 상태처럼 로직이 걸린 코드는 CHECK 제약도 건다.
- 예외적으로 외부 업체는 마스터 테이블에 둔다 (13-6, 규칙 5 예외). 업체 종류는 `CMM_CODE`.

## 9. 개인정보 보호 [확정]

| 항목 | 방식 |
|---|---|
| 암호화 대상 | 법정 필수 항목(고유식별정보, 생체정보, 계좌번호, 카드 관련 값, 인증정보) + 휴대폰, 이메일, 상세 주소. 비밀번호는 일방향 해시. 이름, 생년월일, 도로명·지번 주소는 평문 + TDE (2026-11-23 컬럼 검토 C-72·C-73, 모든 도메인). 체형은 대상 아님 |
| 암호화 | 애플리케이션 AES-256-GCM + KMS 봉투 암호화, TDE 병행 |
| 저장 형식 | `_ENC` `RAW` (키 버전 1 + IV 12 + 태그 16 + 데이터 = 평문 + 29바이트). 예외: 평문이 RAW 한도(2000바이트)를 넘을 수 있으면 `BLOB`에 같은 구성으로 저장한다. 현재 대상은 소셜 제공자 사용자 정보 응답 원문 `MBR_LOGIN_ACCOUNT.PROVIDER_PROFILE_JSON_ENC` 1개 (2026-11-23 컬럼 검토 C-49) |
| 검색용 해시 | HMAC-SHA256 + 정규화, `_HASH` `RAW(32)` |
| 비밀번호 | Argon2id (회원, 관리자, 비회원 주문 비밀번호, 결제 PIN). 결과는 `_HASH` `VARCHAR2(255)` (2026-11-23 컬럼 검토 C-70) |
| 마스킹 | 애플리케이션에서. 외부에서 받은 마스킹 값만 그대로 저장 |
| 분리 보관 | `SYS_PII_ARCHIVE` |
| 감사 로그 | 용도별 분리 (개인정보 접속 기록, 관리자 작업, 데이터 변경). 원문 대신 마스킹 값 |

### 개인정보 보유·파기

- 행 단위 파기 테이블에 공통 컬럼 4개를 둔다: `PII_RETENTION_REASON_CD`, `PII_RETENTION_BASE_DT`(이름 후보), `PII_RETENTION_END_DT`, `PII_PURGED_AT`.
- 보유 기간은 `CMM_CODE`에 두고, 법정 보유 코드는 도메인마다 추가한다.
- 파기는 NULL 처리가 기본이다. 파기 대상 컬럼은 NULL 허용, 필수 여부는 애플리케이션에서 검증한다.
- 파기 실행: 이벤트 즉시 + 일 배치(파기 예정일 경과분).
- 백업 보관 기간: 30일.

## 10. 배치·대량 삭제 [확정]

- Oracle 스케줄러: 파기, 만료 행 정리, 파티션 제거, 집계.
- 애플리케이션 배치: 복호화가 필요한 알림 발송, 외부 대사(택배사, PG).
- 실행 이력 테이블과 애플리케이션 배치용 잠금 테이블을 둔다 (`BAT`).
- 대량 삭제: 시간순 일괄 만료 테이블(로그, 인증번호, 토큰)은 파티션 제거, 행별 기한 테이블은 나눠서 DELETE.
- Redis는 쓰지 않는다. 토큰, 인증번호, 로그인 실패 횟수, 최근 본 상품, 중복 요청 키는 DB에 둔다.

## 11. 파티셔닝·인덱스 [후보]

아래는 제안 단계이며 각 도메인에서 확정한다.

- 대용량 거래·로그 테이블은 월 단위(로그성 만료 테이블은 일 단위) `INTERVAL` 파티션을 검토한다.
  - 확정된 것: 검색어 로그 일 단위 파티션(12-2), 알림 발송 이력 월 단위 파티션(13-4).
- 모든 FK 컬럼에 인덱스를 만든다. Oracle은 FK에 인덱스가 없으면 부모 테이블 DML 때 잠금 범위가 커진다.
- 복합 인덱스는 동등 조건 → 범위 조건 순서로 만든다.

## 12. 마이그레이션

- DDL은 Flyway로 관리한다. 파일 경로와 버전 규칙은 미확정이다.
- 데이터 접근 기술(JPA 외)은 DB 설계 범위 밖이며 백엔드 개발 때 정한다.

## 13. 용어 [확정]

설계 문서에 나오는 약어와 용어의 뜻은 `docs/pdf/용어집/DB용어집.pdf`에 정리했다. 그룹과 용어는 아래와 같다.

| 그룹 | 용어 |
|---|---|
| 키와 제약조건 | PK(기본 키), FK(외래 키), UK(고유 키), CK(체크 제약), 복합 PK, 대리 PK, 업무 키 |
