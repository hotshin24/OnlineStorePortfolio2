## 5-2. 취소의 원인 연결

**무엇을 정하나요?**
취소 행이 "왜 생겼는지"를 어떻게 연결할지 정합니다. 취소가 생기는 원인은 세 가지입니다.
- **클레임:** 주문 취소, 반품, 교환. 클레임 도메인(`CLM`)이 다룹니다.
- **주문 변경:** 배송지를 바꿔 도서산간 추가비가 없어질 때의 부분 환불입니다(주문 OC-107 A, `ORD_ORDER_CHANGE_HIST`).
- **시스템 자동 취소:** 금액 불일치(3-3 A), 만료 뒤 승인(3-8 A·4-4 A)

**이미 정한 것**
- 1-3 A: 환불 금액은 클레임 도메인이 계산하고, 결제 도메인은 환불을 실행합니다.
- 주문 OC-107 A: 배송지 변경으로 없어진 추가비의 부분 환불은 주문 변경 이력과 연결합니다.
- 2-2 C: 주문 결제 외에 추가 결제(용도 `ADDITIONAL`)가 있습니다. 클레임 하나가 주문 결제와 추가 결제를 함께 취소할 수 있습니다.
- 5-1 B: 취소 행 테이블이 있고, 취소 사유 코드가 있습니다.
- 선행 6: 여러 대상을 가리키는 테이블은 대상별 FK 컬럼을 두고, 그중 정확히 하나만 채우도록 CHECK를 겁니다.
- 클레임 테이블은 아직 없습니다. 클레임 도메인에서 만듭니다.

**예시로 보면**
1. **반품:** 반품 클레임 `C-…-01`이 확정되어 30,000원을 환불합니다. 취소 행 1건이 이 클레임을 가리킵니다.
2. **교환 뒤 취소:** 교환 클레임에 왕복 배송비 6,000원을 추가 결제로 받았습니다. 그런데 교환이 철회됩니다. 이 클레임 하나에서 추가 결제 6,000원 전액 취소 행 1건이 나옵니다. 같은 클레임에서 원 주문 결제 일부를 취소하는 행도 함께 나올 수 있습니다.
3. **배송지 변경:** 제주에서 서울로 배송지를 바꿔 도서산간 추가비 3,000원을 부분 환불합니다. 원인은 주문 변경 이력 행입니다.
4. **자동 취소:** 만료 뒤 승인된 휴대폰 결제를 자동으로 취소합니다. 클레임도 주문 변경도 없습니다.
5. **CS 조회:** 상담원이 "이 30,000원 환불은 어느 반품 때문인가"를 찾습니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **취소 행에 원인별 FK 컬럼**을 둡니다: 클레임 ID, 주문 변경 이력 ID.<br>• 둘 중 많아야 하나만 채우도록 CHECK를 겁니다.<br>• 사유 코드에 따라 필수 여부를 CHECK로 겁니다. 클레임 사유면 클레임 ID, 주문 변경 사유면 변경 이력 ID가 NOT NULL이고, 자동 취소 사유면 둘 다 NULL입니다. | 선행 6의 규칙과 같은 모양입니다. 예시 1~4를 모두 표현하고 FK로 정합성을 지킵니다. 클레임 하나 : 취소 N(예시 2)이 자연스럽습니다. 예시 5가 조인 하나로 끝납니다. | 클레임 테이블이 생기기 전에는 FK를 걸 수 없어, 클레임 도메인에서 FK를 추가합니다(DDL 순서, 8-D A). |
| B | 원인 유형 코드 + 원인 ID 하나(다형 참조)를 둡니다. | 원인이 늘어도 컬럼이 늘지 않습니다. | FK를 걸 수 없어 없는 클레임을 가리켜도 DB가 모릅니다. 선행 6의 "대상별 FK" 규칙과 다릅니다. |
| C | 취소 행에는 연결을 두지 않고, 클레임 쪽에 취소 행 ID를 둡니다. | 결제 테이블이 클레임을 몰라도 됩니다. | 클레임 하나 : 취소 N(예시 2)을 담으려면 클레임 쪽에 매핑 테이블이 필요합니다. 주문 변경과 자동 취소는 따로 처리해야 합니다. |

**추천: A.**
- 취소는 원인이 분명해야 하는 거래이고, 원인이 두 종류로 정해져 있어 FK 컬럼 두 개로 충분합니다.
- 선행 6과 같은 방식이라 DB가 정합성을 지킵니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 취소 행 컬럼: `CLAIM_ID`(FK는 클레임 도메인에서 건다), `ORDER_CHANGE_HIST_ID`(FK → `ORD_ORDER_CHANGE_HIST`)
- 취소 사유 코드(값 목록):
  - 클레임: `CLAIM_CANCEL`, `CLAIM_RETURN`, `CLAIM_EXCHANGE`
  - 주문 변경: `ORDER_CHANGE`
  - 자동 취소: `AMOUNT_MISMATCH_AUTO_CANCEL`, `ABNORMAL_APPROVAL_AUTO_CANCEL`
  - 운영자 수동: `MANUAL_ADJUSTMENT`. 클레임 없이 운영자가 직접 하는 취소이고, 사유 메모를 필수로 합니다.
- CHECK: 사유 코드별 FK 필수·금지 조합
- 넘길 것 (클레임 도메인): 클레임 확정 때 결제 취소를 요청하는 흐름, 그리고 `CLAIM_ID` FK 추가
