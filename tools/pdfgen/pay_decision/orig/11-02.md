## 11-2. 로그·대사 테이블의 보관 기간과 인덱스

**무엇을 정하나요?**
주문 참조 파티션 밖에 있는 결제 도메인 테이블의 보관 기간과 삭제 방식을 정합니다. 앞에서 넘긴 웹훅 수신함 UK를 GLOBAL로 둘지 LOCAL로 둘지(7-2 A)도 정합니다.

| 테이블 | 성격 | 나온 곳 |
|---|---|---|
| PG 호출 요약 로그 | 로그, 하루 수만 행 | 7-1 C |
| 웹훅 수신함 | 로그, 하루 수천 행 | 7-2 A |
| 대사 실행·불일치 | 업무 기록, 적음 | 7-3 B, 7-4 A |
| PG 성능 집계 | 집계, 3년 보관으로 정함 | 7-6 B |
| PG 장애 기록 | 마스터, 논리 삭제로 정함 | 7-5 A |

**이미 정한 것**
- 선행 4: 로그는 파티션 단위로 제거하고, 나머지는 1년 뒤 물리 삭제합니다.
- 선행 11: 시간순 만료 테이블은 파티션 제거, 행별 기한 테이블은 나눠서 DELETE합니다.
- 8-4 A: 외부 로그 도구의 원문 보관 기간은 DB 요약 로그와 같게 합니다.
- 9-3 A: 결제 IP는 6개월 보관합니다. 차지백 이의 제기 기간(약 120일)을 넘기기 위해서입니다.
- 개인정보 안전성 확보조치 기준 8조: 개인정보 처리 시스템의 접속 기록은 최소 1년(조건에 따라 2년) 보관합니다. 외부 도구 열람 기록이 여기에 해당합니다(8-4 A).

**예시로 보면**
1. **차지백 소명:** 5개월 전 결제에 이의가 들어와 그때의 PG 호출 기록이 필요합니다.
2. **같은 웹훅 재전송:** PG가 같은 웹훅을 3일 뒤에 다시 보냅니다. 이 웹훅이 다른 월 파티션에 들어가도 중복으로 잡혀야 합니다.
3. **세무 조사:** 3년 전 매출 차이를 묻습니다. 그때 대사에서 어떤 불일치를 어떻게 고쳤는지 보여 줘야 합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **로그 1년, 대사 기록 5년**으로 둡니다.<br>• 호출 요약 로그와 웹훅 수신함: 월 인터벌 파티션, 1년(정책값) 뒤 파티션 제거. 외부 원문도 1년입니다.<br>• 웹훅 수신함 UK(PG, 중복 방지 키)는 GLOBAL로 둡니다. 월이 바뀌어도 중복을 막습니다(예시 2). 파티션 제거 때 `UPDATE GLOBAL INDEXES`를 씁니다.<br>• 호출 요약 로그는 UK가 없어 인덱스를 모두 LOCAL로 둡니다.<br>• 대사 실행·불일치: 파티션 없이 5년(정책값) 뒤 나눠서 DELETE합니다(행이 적음). | 예시 1(6개월 이내)과 예시 3(5년)을 모두 덮습니다. 1년은 접속 기록 최소 기간과도 맞습니다. 중복 방지가 파티션 경계에서 깨지지 않습니다. | 웹훅 수신함의 GLOBAL 인덱스는 월 1회 제거 때 갱신 시간이 걸립니다(하루 수천 행 규모라 작음). |
| B | 로그 3개월(주문 IP와 같음), 대사 기록 1년(선행 4 기본값)으로 둡니다. LOCAL UK를 위해 중복 방지 키에 수신 월을 넣습니다. | 가장 작게 보관합니다. 인덱스가 모두 LOCAL입니다. | 예시 1의 차지백 소명 때 기록이 없을 수 있습니다. 월 경계를 넘는 재전송(예시 2)을 DB가 막지 못합니다. 예시 3에 답할 수 없습니다. |
| C | 로그와 대사 기록 모두 결제 행과 같이 주문 월 + 10년 동안 보관합니다. | 어떤 조사에도 답합니다. | 호출 로그가 10년 동안 수억 행이 됩니다. 결제 행에 이미 결과가 있어 로그를 오래 둘 이유가 작습니다. |

**추천: A.**
- 로그는 "결제 행이 왜 이렇게 되었나"를 분쟁 기간 안에 설명하는 용도라 1년이면 충분합니다. 결과 자체는 결제 행이 10년 동안 갖고 있습니다.
- 대사 불일치와 해결 기록은 장부를 고친 근거라, 거래 기록과 같은 5년 동안 남겨야 합니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 정책값(`CMM_CODE`):
  - PG 호출 로그 보관 개월(12)
  - 웹훅 수신함 보관 개월(12)
  - 대사 기록 보관 연수(5)
- 파티션 제거 배치(Oracle 스케줄러, 선행 11):
  - 매월 보관 기간이 지난 로그 파티션을 제거합니다.
  - 웹훅 수신함은 `UPDATE GLOBAL INDEXES`를 붙입니다.
- 웹훅 수신함에서 "수신·조회 실패" 상태로 남은 행은 제거 대상 파티션에 있어도 먼저 운영자 확인으로 넘깁니다. 배치는 해당 파티션에 미처리 행이 있으면 제거를 미루고 알립니다.
- 대사 테이블 삭제 배치: 실행 일자 + 5년이 지난 실행 행과 그 불일치 행을 나눠서 DELETE합니다.
- 외부 로그 도구 보관 기간 1년, 열람 기록 2년 설정은 운영 설정으로 넘깁니다(DB 밖).

11-2는 A로 메모해 두었습니다.
- PG 호출 로그와 웹훅 수신함은 월 파티션에 두고 1년 뒤 제거합니다. 외부 원문도 1년 보관합니다.
- 대사 기록은 5년 뒤 나눠서 지웁니다.
- 웹훅 수신함 UK는 GLOBAL로 둡니다.
