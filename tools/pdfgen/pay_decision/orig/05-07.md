## 5-7. 과다 환불의 방지와 회수

**무엇을 정하나요?**
과다 환불은 낸 돈보다 많이 돌려주는 사고입니다. 이미 정한 CHECK로 막히지 않는 경우를 어떻게 찾아내고, 이미 나간 돈을 어떻게 되찾을지 정합니다.

**이미 막아 둔 것**
- 결제 행 하나 안에서는 CHECK가 막습니다: 취소 누계 + 처리 중 + PG 밖 환불 누계 ≤ 승인 금액 (2-7 A, 5-1 B, 5-4 A)
- 주문 전체(PG + 적립금 + 예치금)에서는 주문 OC-95 B가 막습니다. 클레임을 확정할 때 주문 행을 잠그고 환불 합계가 결제 금액을 넘지 않는지 검사합니다.
- 같은 환불 요청이 두 번 들어오는 것은 취소 요청 중복 방지 키(5-1 B)가 막습니다.
- 환불 배분은 주문 때 배분값을 그대로 씁니다(5-3 A).

**그래도 남는 경우 (예시)**
1. **PG 관리자 화면에서 직접 취소:**
   - 상담원이 급한 마음에 PG 관리자 화면에서 30,000원을 직접 취소합니다.
   - 같은 반품을 우리 시스템에서도 처리해, 적립금 2,000원과 예치금 8,000원을 복원하고 PG 취소도 요청합니다.
   - PG는 이미 취소된 금액만큼 거절하거나, 잔액이 남아 있으면 또 취소합니다.
2. **우리 DB가 모르는 PG 취소:** 다음 날 대사(7-3)에서 PG에만 있는 30,000원 취소가 나옵니다. 이것을 우리 취소 행으로 들여오면 CHECK에 걸릴 수 있습니다.
3. **계산 오류:** 클레임 도메인의 버그로 적립금이 두 번 복원됐습니다. 고객이 그 적립금을 이미 다른 주문에 썼습니다.
4. **이미 나간 돈:** 과다 환불 15,000원이 확인됐습니다. 고객에게 다시 받아야 합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **찾아서 기록하고, 동의를 받아 회수합니다.**<br>• PG 관리자 화면 직접 취소는 운영 규칙으로 금지하고, 장애 때만 허용합니다.<br>• 대사(7-3)가 PG에만 있는 취소를 찾으면 취소 행으로 들여옵니다. 사유 `PG_CONSOLE_CANCEL`, 행위자 `EXTERNAL`입니다.<br>• 들여올 때 CHECK에 걸리면 운영자 확인 대상으로 올립니다.<br>• 회수 방법: 고객에게 추가 결제(2-2 C의 `ADDITIONAL`, 사유 "환수")를 요청하거나, 고객이 동의하면 예치금에서 차감합니다.<br>• 받지 못한 금액은 정산 도메인에서 손실로 처리합니다. | 예시 1·2의 PG 직접 취소도 우리 DB와 맞춰집니다. 회수가 기존 구조(추가 결제, 예치금 원장)로 기록됩니다. 고객 동의 없이 잔액을 빼지 않습니다. | 운영자 확인 화면과 환수 요청 흐름이 필요합니다. |
| B | 알림만 하고, 처리는 DB 밖에서 수작업으로 합니다. | 구조가 늘지 않습니다. | 예시 2의 PG 취소가 우리 DB에 없어 대사 불일치가 계속 남습니다. 회수 기록이 흩어집니다. |
| C | 고객의 예치금·적립금 잔액에서 자동으로 차감합니다. | 회수가 빠릅니다. | 동의 없이 고객 자산을 빼는 것이라 분쟁과 법적 문제가 생길 수 있습니다 [확인 필요: 법무]. |

**추천: A.**
- 과다 환불의 가장 흔한 원인은 시스템 밖의 수작업(PG 관리자 화면)입니다. 금지 규칙에 더해, 대사가 찾아낸 것을 다시 DB로 들여와 기록을 하나로 맞춰야 합니다.
- 회수는 새 구조 없이 이미 정한 추가 결제와 예치금 원장으로 처리합니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 취소 사유 코드 추가: `PG_CONSOLE_CANCEL`(PG 관리자 화면 직접 취소)
- 결제 용도 코드 `ADDITIONAL`의 추가 결제 사유에 "과다 환불 환수" 값을 넣습니다. 추가 결제 사유 코드는 5-10에서 정합니다.
- 예치금 원장에 차감 사유 "과다 환불 환수(고객 동의)"가 생깁니다(12-x).
- 넘길 것:
  - 정산 도메인: 회수하지 못한 금액의 손실 처리
  - 관리자 도메인: PG 관리자 화면 접근 권한 통제

<!--ANSWER-->
**사용자:** a

5-7은 A로 메모해 두었습니다. PG 관리자 화면에서 직접 취소하는 것은 금지합니다. 대사에서 찾은 PG 쪽 취소는 우리 DB로 들여옵니다. 과다 환불은 고객 동의를 받아 회수합니다.
