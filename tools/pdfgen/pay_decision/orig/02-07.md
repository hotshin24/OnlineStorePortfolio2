## 2-7. 결제 금액 컬럼과 취소 가능 잔액

**무엇을 정하나요?**
결제 행에 둘 금액 컬럼과, 부분 취소가 여러 번 일어날 때 "지금까지 취소한 금액"과 "더 취소할 수 있는 금액"을 어떻게 관리할지 정합니다. 잔액을 잘못 계산하면 승인 금액보다 많이 환불하는 사고(과다 환불, 5-7)가 납니다.

**이미 정한 것**
- 선행 3: 원화 금액은 `NUMBER(15)`입니다.
- 선행 4: 거래 행은 지우지 않고 반대 금액 행으로 정정합니다. 취소는 별도 취소 행으로 남깁니다(5-1에서 구조를 정함).
- 주문 6-7 A: 주문에 PG로 보낸 과세·부가세·면세 금액이 있습니다. 결제 행에서의 과세·면세 분할은 6-8에서 정합니다.
- 2-2 C: 주문 결제로 승인되는 결제는 주문당 1건입니다.
- 용어집 7장: 가상 컬럼(저장하지 않고 식으로 계산하는 컬럼)을 이미 정의했습니다.

**법에서 오는 조건 (여신전문금융업법)**
- 19조 5항 2호: 실제 매출 금액보다 많이 승인받으면 안 됩니다. 그래서 승인 금액은 요청 금액과 같아야 하고, 요청 금액은 주문의 PG 결제 금액과 같아야 합니다.
- 19조 4항: 가맹점 수수료를 고객에게 떠넘기면 안 됩니다. 결제 수수료를 더 받는 금액 컬럼은 두지 않습니다.

**예시로 보면**
주문 PG 결제 금액은 95,000원입니다.
1. **승인:** 요청 95,000원, 승인 95,000원, 취소 누계 0원, 잔액 95,000원
2. **1차 부분 취소:** 3만 원짜리 상품을 반품합니다. 취소 누계 30,000원, 잔액 65,000원
3. **2차 부분 취소:** 다른 상품 반품으로 70,000원을 취소하려 합니다. 잔액 65,000원을 넘으므로 DB가 막아야 합니다.
4. **동시 취소:** 상담원 두 명이 같은 결제를 거의 동시에 2만 원씩 부분 취소합니다. 둘 다 "잔액 65,000원"을 읽고 쓰면 누계가 하나만 반영될 수 있습니다.
5. **금액 불일치:** 결제창을 연 뒤 고객이 다른 탭에서 쿠폰을 바꿔 주문 금액이 93,000원이 됐는데, PG 승인은 95,000원으로 돌아옵니다. 승인 금액 검증(3-3)에서 걸러야 합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **요청 금액, 승인 금액, 취소 누계 금액**을 저장하고, **잔액은 가상 컬럼**(승인 − 취소 누계)으로 둡니다.<br>• CHECK: 0 ≤ 취소 누계 ≤ 승인 금액<br>• 승인됐으면 승인 금액 = 요청 금액<br>• 취소할 때는 결제 행을 잠그고(`SELECT … FOR UPDATE`) 취소 행을 넣은 뒤 누계를 더합니다(3-6). | 예시 3을 CHECK가 막습니다. 예시 4는 행 잠금으로 순서대로 처리됩니다. 잔액이 계산식이라 누계와 어긋날 일이 없습니다. 목록 화면이 취소 행을 합산하지 않고 잔액을 바로 읽습니다. | 취소 행 합계와 누계가 같아야 한다는 규칙을 애플리케이션이 지키고, 대사(7-3)로 확인해야 합니다. |
| B | 승인 금액만 저장하고, 취소 누계와 잔액은 취소 행을 그때그때 합산합니다. | 같은 값이 두 곳에 없습니다. | 예시 3을 CHECK로 막을 수 없어 애플리케이션이 매번 합산해 검사해야 합니다. 목록과 대사 쿼리마다 합산이 필요합니다. |
| C | 승인 금액, 취소 누계, 잔액을 모두 일반 컬럼으로 저장하고 애플리케이션이 갱신합니다. | 단순합니다. | 잔액과 누계가 어긋날 수 있습니다. A의 가상 컬럼보다 나은 점이 없습니다. |

**추천: A.**
- 과다 환불은 결제 도메인에서 가장 돈이 많이 새는 사고라, 마지막 방어선을 DB CHECK에 둡니다.
- 누계 컬럼 하나를 행 잠금 아래에서만 바꾸므로 동시성 규칙이 단순합니다. 취소 행과 누계는 매일 대사로 맞춰 봅니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 컬럼:
  - `REQUEST_AMT`(요청 금액)
  - `APPROVED_AMT`(승인 금액, 승인 전에는 NULL)
  - `CANCELED_AMT`(취소 누계, 기본값 0)
  - `CANCELABLE_AMT`(취소 가능 잔액, 가상 컬럼)
- CHECK:
  - `CANCELED_AMT BETWEEN 0 AND NVL(APPROVED_AMT, 0)`
  - 상태가 승인 이후이면 `APPROVED_AMT = REQUEST_AMT`
- 넘기는 것:
  - 요청 금액 = 주문 PG 결제 금액은 테이블 사이의 규칙이라 CHECK로 걸 수 없습니다. 결제 행을 만들 때 애플리케이션이 검증합니다(3-3).
  - 과세·부가세·면세 금액과 그 취소 누계는 6-8에서 정합니다.
  - 취소 행 합계와 누계의 대사는 7-3에서 정합니다.
