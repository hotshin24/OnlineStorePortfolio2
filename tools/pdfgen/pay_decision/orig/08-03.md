## 8-3. 결제 도메인 식별번호의 암호화 범위

**무엇을 정하나요?**
앞 패턴들에서 "암호화 여부는 8-3에서"로 미뤄 둔 값들을 한 번에 정합니다.

| 값 | 위치 | 나온 곳 |
|---|---|---|
| 가상계좌 번호 | 결제 행 | 2-4 A |
| 환불 계좌번호 | 취소 행 | 5-6 A |
| 휴대폰 결제 번호 | 결제 행 | 2-4 A |
| 현금영수증 식별번호(휴대폰 / 카드 / 사업자번호) | 결제 행, 발급 행 | 6-1 C |
| 세금계산서 받는 자 사업자등록번호 | 세금계산서 행 | 6-5 A |
| PG 카드 식별 값 | 결제 행 | 8-1 A |

**이미 정한 것**
- 선행 5:
  - 암호화 대상은 법정 필수 항목 + 휴대폰, 이메일, 상세 주소입니다.
  - 이름과 예금주는 평문 + TDE입니다(C-72).
  - PG에서 받은 마스킹 값은 그대로 저장합니다.
  - 암호문은 `RAW`(평문 + 29바이트)입니다.
- 회원 도메인:
  - 환불 계좌번호는 "법정 암호화 대상"으로 보아 암호문입니다.
  - 현금영수증 기본 식별번호(휴대폰·카드·사업자번호)는 암호문입니다(25-1 B).
- 계좌이체 계좌번호는 PG가 준 마스킹 값을 그대로 저장합니다(2-4 A).

**예시로 보면**
1. **가상계좌 번호 `1002-345-678901`:** 고객의 계좌가 아니라, 이 주문의 대금을 받으려고 회사(PG)가 잠시 내준 수납 계좌입니다. 입금이 끝나면 쓸모가 없습니다.
2. **환불 계좌 `110-123-456789`:** 고객 본인의 계좌입니다. 유출되면 고객이 피해를 봅니다.
3. **휴대폰 결제 번호 `010-1234-5678`:** 선행 5의 암호화 대상(휴대폰)입니다.
4. **현금영수증 식별번호:** 한 컬럼에 휴대폰 번호와 사업자번호가 섞여 들어옵니다.
5. **세금계산서 사업자번호 `123-45-67890`:**
   - 국세청에 그대로 보내야 하는 값이고, 사업자 조회 서비스로 누구나 확인할 수 있습니다.
   - B2B 고객 응대 때 이 번호로 검색합니다.
6. **PG 카드 식별 값:** PG가 만든 되돌릴 수 없는 토큰입니다. 카드번호를 알아낼 수 없습니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 예시 2~5를 모두 암호문 + 마스킹 값으로 둡니다. 예시 1·6은 평문입니다. | 규칙이 하나라 단순합니다("고객 식별번호는 모두 암호화"). | 예시 5의 사업자번호 검색에 검색용 해시가 따로 필요합니다. 국세청 전송 때마다 복호화합니다. |
| **B** | 예시 2·3·4는 암호문 + 마스킹 값으로 둡니다. 예시 5(세금계산서 사업자번호)와 예시 1·6은 평문 + TDE로 둡니다.<br>• 현금영수증 식별번호는 사업자번호가 들어와도 휴대폰과 같은 컬럼이므로 암호문입니다(회원 25-1 B와 같음). | 회원 도메인과 기준이 같습니다(환불 계좌, 현금영수증 식별번호 암호문). 공개 정보인 세금계산서 사업자번호를 일반 인덱스로 검색합니다. 쓸모가 끝나는 수납 계좌를 암호화하는 비용을 들이지 않습니다. | 개인사업자의 사업자번호도 평문이 됩니다. 이 번호가 개인정보인지는 [확인 필요: 법무]입니다. |
| C | 예시 1~6을 모두 암호화합니다. | 가장 보수적입니다. | 선행 5를 넓히는 것이 됩니다. 법보다 넓게 암호화했다는 지적으로 범위를 줄인 C-72·C-73의 방향과 반대입니다. |

**추천: B.**
- 기준을 "고객에게 피해를 줄 수 있는 식별번호인가"로 두면, 고객 계좌와 휴대폰 번호는 암호화하고, 공개 사업자번호와 일회용 수납 계좌는 평문 + TDE로 충분합니다.
- 회원 도메인과 같은 값(환불 계좌, 현금영수증 식별번호)은 같은 방식으로 다뤄, 회원 테이블에서 복사할 때 형식이 바뀌지 않습니다.

**B를 고르면 생기는 것 (이름은 후보)**
- 암호문 + 마스킹 컬럼:
  - 취소 행 `REFUND_ACCOUNT_NUMBER_ENC`(`RAW(59)`, 회원과 같은 길이) + `REFUND_ACCOUNT_NUMBER_MASKED`
  - 결제 행 `MOBILE_PHONE_NUMBER_ENC` + `MOBILE_PHONE_NUMBER_MASKED`
  - 결제 행·발급 행 `CASH_RECEIPT_ID_NO_ENC`(`RAW(49)`, 회원과 같은 길이) + `CASH_RECEIPT_ID_NO_MASKED`
- 평문 + TDE:
  - 결제 행 `VIRTUAL_ACCOUNT_NO`
  - 세금계산서 행 `BUYER_BUSINESS_REGISTRATION_NO`(일반 인덱스)
  - 결제 행 `PG_CARD_IDENTIFIER_VAL`
- 휴대폰 결제 번호의 검색용 해시(부정 결제 분석용)는 9분야에서 필요하면 정합니다.
- [확인 필요: 법무] 개인사업자 사업자번호의 개인정보 해당 여부

**사용자:** b

8-3은 B로 메모해 두었습니다. 환불 계좌, 휴대폰 결제 번호, 현금영수증 식별번호는 암호문 + 마스킹 값으로 둡니다. 세금계산서 사업자번호, 가상계좌 번호, PG 카드 식별 값은 평문 + TDE입니다.
