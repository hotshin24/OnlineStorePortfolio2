## 3-2. 결제 상태 이력

**무엇을 정하나요?**
결제 상태가 바뀔 때마다 그 기록(언제, 무엇에서 무엇으로, 누가, 왜)을 어디에 남길지 정합니다.

**이미 정한 것**
- 선행 6:
  - 대량 도메인(주문·클레임 후보)은 전용 상태 이력 테이블을 둡니다. 나머지는 `SYS_STATUS_HIST`에 둡니다.
  - 결제는 후보 목록에 없으므로 이 도메인에서 정합니다.
  - 외부 연동 로그는 도메인·업체별 전용 테이블에 둡니다(7-1).
  - 관리자 작업은 관리자 작업 로그에 남깁니다.
- 3-1 B: 승인 상태는 7개 값입니다. 취소는 상태가 아니라 금액이고, 취소 행(5-1)에 건별로 남습니다.
- 2-1 A: 결제 행은 주문 수의 1.5~2배로 예상합니다.
- 전자상거래법 6조와 시행령 6조: 대금 결제와 재화 공급에 관한 기록은 5년 보존합니다. 보존 방법은 8-6에서 정합니다.

**예시로 보면**
1. **정상 카드 결제:** 준비 10:00:00 → 인증 완료 10:00:41 → 승인 10:00:43. 바뀐 일은 2번입니다.
2. **결과 불명 해소:** 인증 완료 → 결과 불명(승인 응답 시간 초과) → 5분 뒤 PG 조회 배치가 승인을 확인합니다 → 승인
   - 나중에 "얼마 동안 결과 불명이었나", "누가 어떻게 확정했나"를 묻습니다.
3. **관리자 수동 확정:** PG 조회도 실패해 운영자가 PG 관리자 화면에서 확인한 뒤 수동으로 "실패"로 바꿉니다. 누가, 무슨 근거로 바꿨는지가 남아야 합니다.
4. **분쟁:** 1년 뒤 고객이 "결제창에서 취소했는데 돈이 빠졌다"고 항의합니다. 각 단계 시각과 PG가 보낸 원문이 필요합니다.
5. **규모:** 하루 결제 행 2만 건 × 상태 변경 평균 2~3번이면, 이력은 하루 4~6만 행, 연 1,500만~2,000만 행입니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | **결제 전용 상태 이력 테이블**을 둡니다. 컬럼은 결제 ID, 이전 상태, 새 상태, 변경 일시, 행위자, 변경 사유, 확정 경로(동기 응답 / 웹훅 / PG 조회 / 수동)입니다. 결제와 같은 기준으로 파티션을 나눕니다. | 예시 1~3을 한 곳에서 시간순으로 봅니다. 주문 도메인과 같은 방식입니다. | 연 2,000만 행 규모의 큰 테이블이 하나 늘어납니다. 대부분의 내용이 PG 로그(7-1)와 겹칩니다. |
| B | `SYS_STATUS_HIST`에 넣습니다(대상별 FK 컬럼에 결제 ID 추가). | 테이블이 늘지 않습니다. | 선행 6이 "대량은 전용 테이블"이라 정한 이유(범용 테이블 비대화)에 정면으로 걸립니다. 결제 규모면 범용 이력의 대부분을 결제가 차지합니다. |
| **C** | **이력 테이블 없이, 결제 행에 단계별 일시 컬럼**을 둡니다: 인증 완료, 승인, 실패, 만료, 결과 불명 발생, 결과 확정. 여기에 확정 경로 코드를 더합니다.<br>• 원문과 상세 흐름은 PG 연동 로그(7-1)가 맡습니다.<br>• 수동 변경(예시 3)은 관리자 작업 로그에 남깁니다.<br>• 취소는 취소 행(5-1)에 남습니다. | 상태가 7개이고 한 방향으로만 흐르므로, 각 단계는 일시 컬럼 하나로 충분합니다. 예시 2의 "얼마 동안 결과 불명이었나"가 컬럼 두 개의 차이로 바로 나옵니다. 큰 테이블이 하나 줄어듭니다. | 같은 상태를 두 번 거치는 경우(예: 결과 불명이 두 번)는 마지막 일시만 남고 앞의 기록은 PG 로그에서 찾아야 합니다. 예시 4는 결제 행, PG 로그, 관리자 로그를 함께 봐야 합니다. |

**추천: C.**
- 주문 상태는 여러 사람과 단계가 오가며 바뀌지만, 결제 승인 상태는 PG 이벤트가 한 방향으로 움직입니다. 그래서 이력 테이블이 담을 정보가 일시 컬럼과 PG 로그에 이미 있습니다.
- 사람이 바꾸는 경우(예시 3)는 드물고, 선행 6에 따라 관리자 작업 로그가 그 용도입니다.
- 단, PG 로그의 보관 기간(11-2)이 5년보다 짧으면 예시 4의 원문이 먼저 사라질 수 있습니다. 8-6과 11-2에서 이 점을 함께 정합니다.

**C를 고르면 생기는 것 (이름은 후보)**
- 일시 컬럼:
  - `AUTHENTICATED_AT`, `APPROVED_AT`, `FAILED_AT`, `EXPIRED_AT`
  - `UNKNOWN_OCCURRED_AT`, `RESULT_CONFIRMED_AT`
- 확정 경로 코드 `RESULT_CONFIRM_ROUTE_CD`: `SYNC_RESPONSE`, `WEBHOOK`, `PG_INQUIRY`, `MANUAL`
- CHECK:
  - 상태가 `FAILED`면 `FAILED_AT`이 NOT NULL입니다. 다른 상태도 이와 같습니다.
  - 확정 경로가 `MANUAL`이면 결과 확정 사유가 NOT NULL입니다.
- 할 일: PG 로그 보관 기간과 5년 보존 의무를 8-6·11-2에서 맞춥니다.
