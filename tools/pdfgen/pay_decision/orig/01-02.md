## 1-2. 적립금·예치금 원장의 소속

**무엇을 정하나요?**
적립금 원장과 예치금 원장(그리고 예치금 출금 요청)을 어느 도메인 접두어에 둘지입니다. 원장의 **구조**는 선행 15에서 정했지만 **소속**은 정하지 않았습니다. 그래서 회원 도메인에도 주문 도메인에도 원장 테이블이 없습니다. 접두어는 19개로 고정이라(선행 3) `PNT` 같은 새 접두어는 만들 수 없습니다.

**이미 정한 것**
- 선행 15:
  - 적립금은 증감 원장 + 적립 건별 차감 기록이고, 원장 상태는 예정·확정·취소입니다.
  - 예치금은 별도 원장 + 건별 차감 기록 + 출금 요청 테이블입니다.
  - 환불 계좌는 회원 테이블에 둡니다.
- 주문 6-4 A, OC-26 A: 주문에서 쓴 적립금·예치금은 주문 상품별 할인 배분 행으로 남깁니다. 출처 코드는 구매 적립 적립금, 기타 적립금, 예치금입니다.
- 주문 6-8 A: 결제 완료 때 원장에 주문 상품별 "예정" 행을 만듭니다(주문 상품 ID FK).
- 주문 1-4 A: 결제 대기 때 예약(원장 "예정" 행)하고, 결제 완료 때 확정하고, 만료·실패 때 되돌립니다.
- 회원 도메인:
  - 탈퇴 때 예치금을 환불 계좌로 자동 출금합니다(28-7).
  - 계정 병합 때 적립금을 원장 이동 거래로 옮깁니다(29-2 A).
  - 적립금 소멸 예정 알림 수신 여부, 쿠폰·적립금 사용 제한(제재)이 회원 테이블에 있습니다.

**예시로 보면**
1. **적립:** 회원이 니트를 사고 구매 확정합니다. 3,000원이 "예정"에서 "확정"이 되고, 리뷰를 쓰면 500원이 더 적립됩니다.
2. **사용:** 다음 주문에서 적립금 3,500원과 예치금 1만 원을 쓰고 나머지를 카드로 냅니다.
   - 주문 할인 배분 행에 상품별로 나뉘어 남습니다.
   - 원장에는 사용 거래 2건이 남습니다.
3. **환원:** 그 주문을 반품합니다. 쓴 적립금과 예치금이 원장에 되돌림 거래로 돌아옵니다.
4. **예치금 출금:** 회원이 예치금 2만 원을 계좌로 돌려 달라고 요청합니다. 출금 요청 → 1원 인증된 환불 계좌로 송금 → 원장 차감이 일어납니다.
5. **소멸:** 1년 동안 쓰지 않은 적립금 800원이 소멸합니다.

예시 2·3은 결제 흐름 한가운데 있고, 예시 1·5는 프로모션 정책(얼마를 언제 줄지)과 가깝고, 예시 4는 고객 돈을 돌려주는 일입니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 적립금·예치금 원장, 차감 기록, 출금 요청을 모두 결제 도메인(`PAY_`)에 둡니다. 적립률·이벤트 적립 같은 "얼마를 줄지"는 프로모션 도메인이 정하고, 원장에 행을 쓰는 것은 결제 도메인입니다. | 예시 2·3의 차감·환원이 PG 결제·취소와 같은 도메인, 같은 트랜잭션 규칙(잠금 순서) 안에서 처리됩니다. 예치금은 고객이 맡긴 돈이라 결제 쪽 대사·보관 통제를 같이 받습니다. 예시 4의 송금은 환불 송금(5-5)과 같은 연동을 씁니다. | 결제 도메인 테이블이 4~5개 늘어납니다. 프로모션의 적립 정책과 원장이 도메인이 다릅니다(정책 ID를 원장 행에 FK로 둠). |
| B | 적립금·예치금 모두 프로모션 도메인(`PRM_`)에 둡니다. | 예시 1·5(적립·소멸 정책)와 원장이 같은 곳입니다. | 예치금은 혜택이 아니라 고객 돈이라 성격이 맞지 않습니다. 결제·환불 때마다 결제 도메인이 프로모션 원장을 건드립니다. |
| C | 회원 도메인(`MBR_`)에 둡니다. | 회원 잔액이라 회원과 가깝습니다. 탈퇴 자동 출금(28-7)이 회원 도메인 안에서 끝납니다. | 확정 단계인 회원 도메인을 다시 열어야 합니다. 주문 상품 FK(6-8 A)와 결제 FK가 회원 테이블로 들어와 회원 도메인이 주문·결제에 묶입니다. |
| D | 적립금은 프로모션, 예치금은 결제 도메인에 둡니다. | 성격대로 나뉩니다. | 예시 2의 결제 한 번에 두 도메인의 원장을 차감합니다. 원장 구조(건별 차감, 상태)가 같은데 두 곳에 따로 설계합니다. |

**추천: A.**
- 원장이 실제로 바뀌는 순간(예약, 확정, 되돌림, 환원)은 모두 결제 상태가 바뀔 때입니다(주문 1-4 A).
- "얼마를 줄지"(정책)와 "잔액이 어떻게 움직였는지"(원장)를 나누면 경계가 분명합니다. 정책은 프로모션, 원장은 결제입니다.
- 회원 도메인을 다시 열지 않아도 됩니다. 탈퇴 자동 출금은 회원 도메인이 결제 도메인의 출금 요청을 만드는 방식으로 연결합니다.

**A를 고르면 결제 도메인에 생기는 것 (이름은 모두 후보)**
- 적립금 원장, 적립금 차감 기록 (선행 15)
- 예치금 원장, 예치금 차감 기록, 예치금 출금 요청 (선행 15)
- 원장 운영 규칙(잔액 관리, 차감 순서, 소멸, 확정 시점, 동시성)은 분야 12에서 정합니다.

**A를 고르면 다른 도메인에 넘길 것**
- 프로모션: 적립 정책 ID를 원장 행이 참조합니다. 리뷰·이벤트 적립은 프로모션이 요청하고 결제가 원장에 씁니다.
- 회원: 탈퇴 자동 출금(28-7)과 계정 병합 이동(29-2 A)은 결제 도메인의 출금 요청·이동 거래로 처리합니다. 회원 쪽 문서에는 연결 대상 이름만 바뀝니다.
