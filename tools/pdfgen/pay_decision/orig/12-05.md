## 12-5. 적립금·예치금 잔액과 동시 사용 제어

**무엇을 정하나요?**
회원의 적립금·예치금 잔액을 어디서 읽을지 정합니다. 잔액 컬럼을 따로 둘지, 적립 건의 남은 금액 합계로 계산할지가 질문입니다. 같은 회원이 동시에 두 주문에서 쓸 때 초과 사용을 어떻게 막을지도 함께 정합니다.

**이미 정한 것**
- 12-1 A, 12-2 A: 적립·입금 행마다 남은 금액(`REMAINING_AMT`)이 있습니다. 차감할 때 같은 트랜잭션에서 줄입니다.
- 3-6 A: 잠금 순서는 주문 → 결제 → 회원·한도 → 원장 → 예약입니다.
- 주문 OC-122: 미성년 한도 검사 때 회원 행을 잠급니다.
- 7-4 A: 매일 "잔액 ≠ 원장 합계"(`BALANCE_DIFF`)를 대사합니다.
- 회원 테이블에는 지금 적립금·예치금 잔액 컬럼이 없습니다.

**예시로 보면**
1. **동시 사용:** 적립금 5,000원인 회원이 PC와 앱에서 동시에 각각 4,000원을 쓰는 주문을 냅니다. 하나는 실패해야 합니다.
2. **화면 표시:** 모든 페이지 상단에 "적립금 5,000원 · 소멸 예정 1,000원"을 보여 줍니다.
3. **자정 소멸:** 기한이 오늘까지인 적립금 1,000원은 소멸 배치가 돌기 전인 00:10에도 쓸 수 없어야 합니다.
4. **활성 적립 건 수:** 회원 한 명의 남은 금액 > 0 적립 건은 보통 수 개에서 수십 개입니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 회원 테이블에 적립금·예치금 잔액 캐시 컬럼을 두고, 원장과 같은 트랜잭션에서 바꿉니다. 회원 행 잠금으로 동시 사용을 막습니다. | 예시 2가 회원 행 한 번 읽기로 끝납니다. | 캐시가 두 겹(건별 남은 금액 + 회원 잔액)이 되어 어긋날 곳이 늘어납니다. 예시 3처럼 기한이 지난 금액은 배치가 돌기 전까지 잔액에 남아 있어, 결국 건별로 다시 계산해야 합니다. 회원 도메인 테이블에 결제 쪽 값이 들어갑니다. |
| B | 결제 도메인에 회원별 잔액 테이블(회원과 1:1)을 따로 두고, A처럼 같이 바꿉니다. | 회원 테이블을 건드리지 않습니다. | A의 단점에 더해, 규칙 5 예외(1:1 테이블)가 하나 늘어납니다. |
| **C** | **잔액 컬럼을 두지 않고, 확정 적립·입금 행 중 기한이 남은 건의 남은 금액 합계로 계산합니다.**<br>• 동시 사용은 회원 행을 `SELECT … FOR UPDATE`로 잠가 회원 단위로 줄 세웁니다(3-6 A의 "회원" 단계).<br>• 잠근 뒤 기한 순으로 적립 건을 읽고 차감합니다.<br>• 기한 조건(`EXPIRES_DT >= 오늘`)을 조회에 넣어 예시 3을 정확히 처리합니다. | 남은 금액이 유일한 캐시라 어긋날 곳이 하나입니다. 예시 3이 배치 시각과 상관없이 정확합니다. 활성 건이 적어(예시 4) 함수 기반 인덱스로 바로 합산됩니다. 회원 테이블에 컬럼을 더하지 않습니다. | 예시 2의 화면 표시마다 합산 쿼리가 돕니다(인덱스 범위 조회, 수십 행). 회원 행 잠금이 적립금을 쓰는 모든 주문에 걸립니다. |

**추천: C.**
- 12-1에서 적립 건의 남은 금액을 이미 캐시로 두었기 때문에, 잔액 컬럼은 같은 정보를 한 번 더 들고 있는 것입니다. 기한 때문에 결국 건별로 다시 봐야 하므로, 잔액 컬럼의 이점이 작습니다.
- 동시성은 회원 행 잠금 하나로 충분합니다. 미성년 한도 검사(OC-122)가 이미 같은 잠금을 쓰고 있어 잠금 순서도 그대로입니다.

**C를 고르면 생기는 것 (이름은 후보)**
- 함수 기반 인덱스:
  - 적립금: (회원, 유효기한). 확정이고 남은 금액이 0보다 큰 행만 키를 갖습니다(12-1 A의 인덱스를 그대로 씀).
  - 예치금: (회원, 출처 유형). 남은 금액이 0보다 큰 입금 행만 둡니다.
- 7-4 A 보완: `BALANCE_DIFF` 검사를 "건별 남은 금액 = 적립(입금) − 차감 합계"로 바꿉니다. 잔액 컬럼이 없기 때문입니다.
- 사용 흐름(정책명세 조문):
  1. 주문 행 잠금
  2. 회원 행 잠금
  3. 기한 순(적립금)이나 카드성 먼저(예치금)로 건을 읽고 차감
  4. 원장·차감 기록 쓰기
- 화면 표시 부하가 문제가 되면 애플리케이션 캐시로 풉니다. DB 컬럼은 더하지 않습니다.
