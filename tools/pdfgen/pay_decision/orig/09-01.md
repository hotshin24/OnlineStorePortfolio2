## 9-1. 부정 결제 탐지(FDS)와 보류

**무엇을 정하나요?**
도용 카드, 계정 탈취, 리셀 목적의 대량 구매 같은 부정 결제를 어떤 방식으로 판정하고, 판정 결과를 어디에 남기고, 결과에 따라 결제·주문을 어떻게 처리할지 정합니다.

**이미 정한 것**
- 주문 도메인:
  - 주문 보류 사유 코드에 `PAYMENT_REVIEW`(결제 확인 필요, PG FDS 판정 등)가 있습니다.
  - 보류 중인 주문은 출고하지 않습니다(7-6 A, OC-72 A).
  - 재판매 의심(`RESALE_SUSPECTED`)은 주문 도메인 8-3 A에서 따로 정했습니다.
- 8-1 A: 같은 카드를 식별하는 값(PG 카드 식별 값)을 결제 행에 둡니다.
- 8-5 B: 결제 행마다 요청 IP, 채널, OS를 둡니다.
- 3-1 B: 실패 사유 코드가 있습니다.
- 여신전문금융업법 16조: 도용 카드 사용은 원칙적으로 카드사가 책임지지만, 카드사는 가맹점에 소명을 요구하고 차지백을 청구합니다(9-3).

**예시로 보면**
1. **속도 이상:** 10분 동안 같은 IP에서 서로 다른 카드 8장으로 결제가 시도됩니다.
2. **새 계정 고액:** 가입한 지 1시간 된 계정이 한정판 패딩 5벌(250만 원)을 결제합니다.
3. **계정 탈취 의심:** 3년 된 회원 계정이 평소와 다른 해외 IP에서, 배송지를 새 주소로 바꾸고 고액을 결제합니다.
4. **정상 고객:** 단골이 연말에 평소보다 많이 삽니다. 막으면 매출을 잃습니다.
5. **판정 결과:**
   - 예시 1: 결제 전에 막습니다(차단).
   - 예시 2·3: 승인은 하되 주문을 보류하고 운영자가 확인합니다(검토).
   - 예시 4: 그대로 통과합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **자체 규칙 기반 판정**을 하고, 결과를 결제 행에 남깁니다.<br>• 규칙 예: 카드·IP·회원별 시도 속도, 가입 직후 고액, 배송지 변경 직후 고액, 비회원 고액<br>• 기준값은 `CMM_CODE` 정책값에 둡니다.<br>• 판정: 통과 / 검토 / 차단<br>　- 차단: 결제를 시도하지 않고 `FAILED`(사유 `FDS_BLOCKED`)로 둡니다.<br>　- 검토: 승인 뒤 주문을 `PAYMENT_REVIEW`로 보류합니다.<br>• PG가 자체 FDS 결과를 주면 함께 저장합니다. | 이미 모으는 값(카드 식별 값, IP, 회원 이력)으로 바로 시작합니다. 판정 근거가 결제 행에 남아 차지백 소명(9-3)에 씁니다. 주문 보류 구조를 그대로 씁니다. | 규칙을 운영하며 계속 고쳐야 합니다. 정교한 패턴(기기 지문, 행동 분석)은 잡기 어렵습니다. |
| B | 외부 FDS 업체(또는 PG 부가 서비스)에 판정을 맡기고, 점수와 판정을 결제 행에 남깁니다. 처리 흐름은 A와 같습니다. | 기기 지문 등 여러 몰의 데이터를 쓴 정교한 판정입니다. | 비용이 듭니다. 판정 근거가 업체 쪽에 있어 설명하기 어렵습니다. 고객 정보를 업체에 보내므로 개인정보 처리 위탁에 해당합니다. |
| C | 자체 판정 없이 PG·카드사 FDS에만 맡깁니다. | 만들 것이 없습니다. | 리셀·계정 탈취처럼 카드사가 보지 않는 패턴을 잡지 못합니다. 차지백 소명 자료가 부족합니다. |

**추천: A.**
- 의류몰의 주된 부정 패턴은 한정판 리셀과 계정 탈취입니다. 카드사 FDS보다 우리 데이터(회원 이력, 배송지 변경, 같은 카드 반복)가 더 잘 잡습니다.
- 결과 컬럼을 판정 방식과 상관없이 정해 두면(점수, 판정, 근거), 나중에 외부 업체(B)를 더해도 구조가 바뀌지 않습니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 결제 행 컬럼:
  - `FDS_DECISION_CD`(`PASS`, `REVIEW`, `BLOCK`)
  - `FDS_SCORE_VAL`
  - `FDS_MATCHED_RULE_JSON`(걸린 규칙 코드 목록)
  - `FDS_EVALUATED_AT`
  - `PG_FDS_RESULT_VAL`(PG가 준 판정, 있으면)
- 실패 사유 코드 추가: `FDS_BLOCKED`
- 검토 판정의 운영자 처리(통과 / 취소)는 주문 보류 해제(주문 도메인)와 결제 취소(5-1, 사유 `MANUAL_ADJUSTMENT`나 FDS 전용 사유)로 처리합니다. FDS 취소 사유 코드를 따로 둘지는 컬럼 검토 때 여쭙겠습니다.
- 규칙 목록을 테이블로 둘지 설정으로 둘지도 컬럼 검토 때 여쭙겠습니다. 지금은 정책값 기준값만 확정합니다.

<!--ANSWER-->
**사용자:** a

9-1은 A로 메모해 두었습니다. 부정 결제는 자체 규칙으로 판정하고, 판정 결과를 결제 행에 남깁니다. 판정이 차단이면 결제를 시도하지 않고, 검토면 승인 뒤 주문을 보류합니다.
