## 5-1. 취소 기록 구조

**무엇을 정하나요?**
결제 취소(전액·부분)를 어떤 행으로 남길지 정합니다. 그리고 PG 취소 요청 전에 DB에서 금액을 어떻게 선점할지 정합니다. 3-6에서 이 선점 방식을 5-1로 넘겼습니다.

**이미 정한 것**
- 선행 4: 거래 행은 지우지 않고 반대 금액 행으로 정정합니다.
- 2-7 A:
  - 결제 행에 취소 누계 금액이 있고, 잔액은 가상 컬럼(승인 − 취소 누계)입니다.
  - CHECK: 0 ≤ 취소 누계 ≤ 승인 금액
- 3-1 B: 취소 상태(없음·부분·전체)는 취소 누계로 계산하는 가상 컬럼입니다.
- 3-4 A: 취소 중복 요청은 5-1에서 정합니다.
- 3-6 A:
  - PG 호출은 트랜잭션 밖에서 합니다.
  - 잠금 순서는 주문 → 결제입니다.
- 자동 취소 사유 코드 두 개가 있습니다: `AMOUNT_MISMATCH_AUTO_CANCEL`(3-3 A), `ABNORMAL_APPROVAL_AUTO_CANCEL`(3-8 A).

**예시로 보면**
승인 금액은 95,000원입니다.
1. **부분 취소 두 번:** 반품 30,000원, 다음 주에 다시 20,000원을 취소합니다. 취소 행 2건이 남고, 취소 누계는 50,000원, 잔액은 45,000원입니다.
2. **PG 응답을 기다리는 동안:**
   - 30,000원 취소를 PG에 요청하고 응답을 기다리는 3초 동안, 다른 상담원이 70,000원 취소를 시도합니다.
   - DB에서 30,000원을 먼저 잡아 두지 않으면 둘 다 "잔액 95,000원"을 보고 통과합니다.
3. **PG 취소 실패:** 30,000원 취소가 PG 오류로 실패합니다. 잡아 둔 금액을 풀고 다시 시도할 수 있게 해야 합니다(5-9).
4. **취소 버튼 두 번:** 상담원이 [환불] 버튼을 두 번 누릅니다. 30,000원이 두 번 취소되면 안 됩니다.
5. **대사:** PG 취소 내역에는 완료된 취소만 있습니다. 처리 중인 취소는 PG에 아직 없습니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | **취소 행 테이블**을 두고, 요청할 때 취소 행(상태: 요청)을 넣으면서 결제 행의 취소 누계에 바로 더합니다. 실패하면 누계에서 다시 뺍니다. | 예시 2를 기존 CHECK 하나로 막습니다. 컬럼이 늘지 않습니다. | 취소 누계에 "처리 중"이 섞여 PG 취소 내역(예시 5)과 맞지 않습니다. 3-1 B의 취소 상태가 처리 중인데도 "전체"로 보일 수 있습니다. |
| **B** | **취소 행 테이블**을 두고, 결제 행에 **취소 처리 중 금액** 컬럼을 하나 더 둡니다.<br>• 요청: 결제 행을 잠그고, 취소 행(요청)을 넣고, 처리 중 금액에 더합니다.<br>• 완료: 처리 중 금액에서 빼고 취소 누계에 더합니다.<br>• 실패: 처리 중 금액에서만 뺍니다.<br>• 잔액 가상 컬럼은 승인 − 취소 누계 − 처리 중으로 계산합니다. | 예시 2를 CHECK로 막습니다. 취소 누계는 항상 "완료된 취소"라 PG 내역과 바로 맞습니다(예시 5). 화면에 "환불 처리 중 30,000원"을 보여 줄 수 있습니다. | 결제 행에 컬럼이 하나 늘고, 상태가 바뀔 때마다 두 금액을 함께 바꿔야 합니다. |
| C | 별도 테이블 없이 결제 테이블에 음수 금액 행을 넣습니다(선행 4의 "반대 금액 행"을 글자 그대로 적용). | 테이블이 늘지 않습니다. | 결제 행의 상태, PG 거래번호 UK(2-8), 주문당 승인 1건 UK(2-2 C)가 취소 행과 섞여 모두 예외 조건이 필요합니다. |

**추천: B.**
- 대사와 정산(1-6)은 "완료된 취소"를 기준으로 하므로, 누계 컬럼이 그 값만 담는 편이 맞습니다.
- 취소 행 테이블은 선행 4의 "반대 금액 행으로 정정"을 전용 거래 행으로 지키는 방식이고, 결제 행의 제약을 흐리지 않습니다.

**B를 고르면 생기는 것 (이름은 후보)**
- 취소 행 테이블(예: `PAY_PAYMENT_CANCEL`):
  - 컬럼: 결제 ID, 취소 순번, 취소 금액, 취소 상태(`REQUESTED` / `COMPLETED` / `FAILED`), 취소 사유 코드, 요청 일시, 완료 일시, PG 취소 거래번호, 실패 사유, 행위자
  - 취소 요청 중복 방지 키: UK, 3-4 A와 같은 방식(예시 4)
  - 과세·면세 취소 금액은 6-8에서 정합니다.
  - 클레임 연결은 5-2에서 정합니다.
- 결제 행 컬럼: `CANCEL_PENDING_AMT`(취소 처리 중 금액, 기본값 0)
- 결제 행 CHECK: `CANCELED_AMT + CANCEL_PENDING_AMT ≤ APPROVED_AMT`
- 가상 컬럼 `CANCELABLE_AMT`의 식을 `APPROVED_AMT − CANCELED_AMT − CANCEL_PENDING_AMT`로 바꿉니다(2-7 A 보완).
- 취소 행이 거래 행이라 시퀀스 CACHE와 파티션은 11-x에서 함께 정합니다.

**사용자:** b

5-1은 B로 메모해 두었습니다. 취소 행 테이블을 두고, 결제 행에 취소 처리 중 금액을 둡니다. 잔액은 승인 금액 − 취소 누계 − 처리 중 금액입니다.
