## 1-3. 환불 금액 산정과 환불 실행의 경계

**무엇을 정하나요?**
환불 한 건을 처리하려면 두 가지를 정해야 합니다. 이 패턴은 둘을 누가 정하고, 두 도메인이 무엇으로 연결되는지입니다.
- **얼마를 돌려줄지:** 반품 배송비 차감, 사은품 미반환 차감 등을 반영한 금액입니다.
- **어떻게 돌려줄지:** 카드 취소, 적립금 환원, 계좌 송금 중 무엇으로 나눌지입니다.

1-1 A에서 PG를 부르는 곳은 결제 도메인 하나로 정했으므로, 실제 실행은 결제 도메인입니다.

**이미 정한 것**
- 1-1 A: 환불 실행은 결제, 환불 금액 산정은 클레임입니다.
- 주문 6-4 A, OC-26 A: 주문 상품마다 할인 출처별 배분 행이 있습니다(쿠폰, 프로모션, 등급, 임직원, 구매 적립 적립금, 기타 적립금, 예치금). 상품 결제 분담액(`ITEM_PAYMENT_AMT`)은 PG 몫입니다.
- 주문 OC-95 B: 환불할 때 주문 행을 잠그고 환불 합계가 결제 금액을 넘지 않는지 검사합니다.
- 주문 OC-107 A: 배송지 변경으로 도서산간 추가비가 없어지면 부분 환불합니다. 주문 변경 이력과 연결합니다.
- 주문 OC-71 A(결제 넘김): 결제 만료 뒤 도착한 승인은 자동 취소합니다.

**예시로 보면**
주문: 재킷 13만 1,450원 + 니트 11만 1,150원. 상품별 배분은 다음과 같습니다.
- 니트 배분: 쿠폰 −1만 원, 적립금 −2천 원, 예치금 −5천 원, 카드(상품 결제 분담액) 9만 4,150원

1. **반품 (클레임 있음):** 니트를 반품합니다(단순 변심, 반품 배송비 3,000원).
   - 클레임이 계산합니다: 돌려줄 금액은 적립금 2천 + 예치금 5천 + 카드 9만 4,150 − 배송비 3천 = 9만 8,150원. 쿠폰 복원 여부도 클레임이 판단합니다.
   - 결제가 실행합니다: 카드 9만 1,150원 부분 취소, 적립금 2천 원 환원, 예치금 5천 원 환원.
2. **만료 뒤 승인 (클레임 없음):** 가상계좌 기한이 지나 주문이 만료됐는데 입금이 들어왔습니다. 고객이 요청한 반품이 아니므로 클레임이 없습니다. 결제 도메인이 스스로 전액 환불합니다.
3. **도서산간 차액 (클레임 없음):** 제주 → 서울로 배송지를 바꿔 추가 배송비 3,000원을 돌려줍니다. 근거는 주문 변경 이력입니다.
4. **PG 실패 후 재시도:** 예시 1의 카드 취소가 PG 장애로 실패해 30분 뒤 다시 보냅니다. 적립금·예치금 환원은 이미 끝났습니다.

예시 2·3처럼 **클레임이 없는 환불**이 있고, 예시 4처럼 **한 환불이 여러 단계로 나뉘어 끝나는** 경우가 있습니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 결제 도메인에 **환불 요청** 테이블을 둡니다. 한 행에는 근거, 총 환불액, 상태(요청 → 처리 중 → 완료 / 일부 실패), 요청·완료 일시가 들어갑니다. 근거는 클레임 ID, 주문 변경 이력 ID, 결제 자체 사유 중 정확히 하나만 채웁니다(선행 6 방식 CHECK). 클레임은 금액을 정해 요청 1행을 만듭니다. 결제 도메인이 배분해 결제 취소 행과 원장 환원 행을 만들고, 각 행은 환불 요청 ID를 가리킵니다. | 예시 2·3의 클레임 없는 환불도 같은 길로 처리합니다. 예시 4처럼 일부만 끝난 상태가 요청 행 하나에 보입니다. "이 반품 환불이 다 끝났나"를 한 행으로 답합니다. 법정 환급 기한(5-8)을 요청 행에 둘 수 있습니다. | 테이블이 하나 늘어납니다. 환불 1건이 1:N 결과 행을 가지는 거래라 규칙 5의 허용 범위로 봅니다. |
| B | 클레임이 수단별 금액(카드 9만 1,150, 적립금 2천, 예치금 5천)까지 정합니다. 결제 취소 행과 원장 환원 행이 클레임 ID를 직접 가리킵니다. 환불 요청 테이블은 없습니다. | 테이블이 늘지 않습니다. | 수단 배분 규칙이 클레임 도메인에 들어갑니다. 예시 2·3은 클레임 ID가 없어 근거를 둘 곳이 따로 필요합니다. "환불이 다 끝났나"를 알려면 여러 행을 모아 봐야 합니다. |
| C | 환불 요청 테이블 없이, 결제 취소 행과 원장 환원 행에 근거 컬럼(클레임 ID / 주문 변경 이력 ID / 결제 사유, 정확히 하나)을 직접 둡니다. 배분은 결제 도메인이 합니다. | 테이블이 늘지 않고, 배분 규칙은 결제에 있습니다. | 한 환불이 취소 1행 + 환원 2행으로 흩어져 묶는 키가 없습니다. 예시 4에서 끝났는지, 기한은 언제인지를 둘 곳이 없습니다. |

**추천: A.**
- 클레임은 "얼마"만 알면 되고 결제 수단을 몰라도 됩니다. 1-1 A의 경계를 그대로 테이블로 옮긴 형태입니다.
- 클레임 없는 환불(만료 뒤 승인, 도서산간 차액, 앞으로 생길 보상 환불)이 같은 길로 들어옵니다.
- 전자상거래법 18조의 환급 기한(반환받은 날부터 3영업일)을 지켰는지 증명하려면 "환불 하나"를 대표하는 행이 있어야 합니다 [확인 필요: 법무, 기산점]. 기한 컬럼은 5-8에서 정합니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 환불 요청 테이블:
  - 환불 요청 ID(PK)와 주문 ID FK
  - 근거: 클레임 ID / 주문 변경 이력 ID / 결제 사유 코드 (정확히 하나, CHECK)
  - 환불 총액과 상태
  - 요청 일시, 완료 일시
- 결제 취소 행과 원장 환원 행의 환불 요청 ID FK
- 클레임에 넘길 것: 환불 금액 산정 결과로 환불 요청 1행을 만들고, 완료 여부는 환불 요청 상태로 받습니다.

**참고**
- 상품별 수단 배분 방식(예시 1처럼 상품 배분 행대로 할지, 수단 순서대로 할지)은 5-3에서 정합니다.
- 환불 수단(카드 취소, 계좌 송금, 예치금으로 받기)은 5-5에서 정합니다.
