**새로 드러난 결정: 카드 가맹점 계약 형태**
- 연매출 4,700억 원 규모의 몰은 PG의 하위가맹점으로 들어가기도 하고, 카드사와 직접 가맹점 계약(직가맹)을 맺기도 합니다.
- 직가맹이면 카드사가 몰에 직접 정산하고, PG는 승인만 중계합니다.
- 어느 쪽이냐에 따라 결제 행에 남길 번호(PG MID / 카드사 가맹점번호)와 대사 상대(PG / 카드사)가 달라집니다.
- 그래서 **1-7 카드 가맹점 계약 형태**를 새 패턴으로 추가합니다.

## 법률 검토 전에 올린 1-5 원문

### 1-5. PG 선택(라우팅) 설정

**무엇을 정하나요?**
PG가 여러 곳이라(선행 13), 결제할 때 이 수단을 어느 PG의 어느 상점 ID(MID)로 보낼지 정하는 규칙이 필요합니다. 이 규칙을 어디에 두고, 장애 때 어떻게 바꿀지를 정합니다.

**이미 정한 것**
- 선행 13:
  - 여러 PG + 간편결제 직접 계약입니다.
  - 결제 대행사 코드 + 거래번호에 UK를 겁니다.
  - 외부 업체 마스터 테이블(`SYS`)이 있습니다.
- 1-4 A: 카드, 자사 원클릭, 외부 간편결제, 가상계좌, 계좌이체, 휴대폰 결제를 받습니다.
- 회원 40-1 D: 자사 원클릭은 빌링키를 발급한 PG로만 결제할 수 있습니다(빌링키는 PG마다 다름).
- 선행 6: 관리자 작업은 용도별 감사 로그(관리자 작업 로그)에 남깁니다.

**예시로 보면**
1. **평소:** 카드는 PG-가(수수료 2.3%), 가상계좌는 PG-나(건당 300원), 휴대폰 결제는 PG-다만 지원합니다. 카카오페이·네이버페이·토스페이는 직접 계약입니다.
2. **장애:** 금요일 밤 PG-가 카드 승인이 실패합니다. 관리자가 카드 결제를 PG-나로 바꾸고, 2시간 뒤 되돌립니다.
3. **기간 설정:** 12월 한 달 동안 PG-나의 무이자 할부 행사가 있어 그 기간만 카드를 PG-나로 보냅니다.
4. **원클릭 예외:** 회원이 등록한 카드의 빌링키는 PG-가가 발급했습니다. PG-가가 장애면 원클릭은 다른 PG로 돌릴 수 없어 "일시 사용 불가"로 표시해야 합니다.
5. **과세 구분 MID:** 같은 PG-가 안에서 과세 상품용 MID와 면세 상품용 MID가 다릅니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **결제 수단 × PG 설정 테이블**을 둡니다. 컬럼은 결제 수단 코드, PG 업체 코드, MID, 우선순위, 사용 여부, 적용 시작·종료 일시, 변경 사유입니다. 결제할 때 지금 유효한 행 중 우선순위가 가장 높은 것을 씁니다. 변경은 관리자 작업 로그에 남고, 결제 행에는 실제로 쓴 PG 코드와 MID를 남깁니다(2-6). | 예시 2를 배포 없이 관리자 화면에서 바꿉니다. 예시 3은 적용 기간으로, 예시 5는 MID 행으로 표현합니다. 수단 × PG의 M:N이라 규칙 5의 허용 범위입니다. | 테이블 1개가 늘어납니다. "유효한 행이 하나도 없으면 그 수단을 화면에서 숨김" 같은 규칙을 애플리케이션이 지켜야 합니다. |
| B | 애플리케이션 설정 파일(환경 설정)에 둡니다. | 테이블이 없습니다. | 예시 2에서 바꾸려면 배포나 재시작이 필요합니다. 언제 누가 바꿨는지가 DB에 없어 장애 기간의 결제를 설명하기 어렵습니다. |
| C | `CMM_CODE`의 결제 수단 코드 행 `ATTR1`~`ATTR5`에 PG 코드와 MID를 넣습니다. | 테이블이 늘지 않습니다. | 수단 하나에 PG 하나만 담겨 예시 3(기간)과 우선순위를 표현할 수 없습니다. 코드 테이블이 운영 설정을 품게 됩니다. |

**추천: A.**
- PG가 여럿인 이유가 장애 대비와 수수료 최적화이므로, 바꾸는 행위가 운영 화면에서 바로 되어야 합니다.
- 예시 4(원클릭)는 이 테이블로 PG를 바꾸지 않습니다. 저장 결제수단의 발급 PG로만 결제하고, 그 PG의 사용 여부가 N이면 원클릭을 숨깁니다. 이 규칙을 설정 테이블 설명에 적습니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 결제 수단 PG 설정 테이블:
  - 컬럼: 결제 수단 코드, PG 업체 코드, MID, 우선순위, 사용 여부, 적용 시작·종료 일시, 변경 사유
  - 중복 방지: UK(수단, PG, MID, 적용 시작 일시)
  - 마스터·설정이라 논리 삭제를 씁니다(선행 4).
- PG 업체 코드는 외부 업체 마스터(`SYS`)의 업체 코드를 씁니다(선행 13). 회원 도메인 저장 결제수단의 결제 대행사 코드도 같은 값 목록입니다.
- 함께 다루는 패턴:
  - 7-5(PG 장애 대응과 전환 기록): 이 테이블을 쓰는 운영 규칙입니다.
  - 2-6(PG사·MID): 결제 행에 남기는 값입니다.
