## 12-2. 예치금 원장과 입금 출처

**무엇을 정하나요?**
선행 15에서 예치금은 "별도 원장 + 건별 차감 기록 + 출금 요청 테이블"로 정했습니다. 여기서는 예치금 원장의 행 구조를 정하고, 특히 **예치금이 어디서 들어온 돈인지(입금 출처)를 건별로 남길지**를 정합니다. 출처가 중요한 이유는 카드로 결제한 돈이 예치금을 거쳐 현금으로 빠져나가는 길이 생기기 때문입니다.

**법에서 오는 조건**
- 여신전문금융업법 19조, 70조: 실제 매출 없이 카드 결제를 현금으로 바꿔 주는 행위(이른바 카드깡)는 금지되고 처벌 대상입니다.
  - 카드 결제 → 반품 → 예치금 환불 → 계좌 출금이 이어지면 결과적으로 카드 결제가 현금이 됩니다.
  - 이 경로를 어디까지 허용할지는 [확인 필요: 법무]입니다.

**이미 정한 것**
- 선행 15: 예치금은 별도 원장, 건별 차감 기록, 출금 요청 테이블을 둡니다. 환불 계좌는 회원 테이블에 둡니다.
- 5-5 A: PG 결제분 환불을 고객이 고르면 예치금으로 받을 수 있습니다(동의 일시 기록).
- 4-4 A: 가상계좌 과오입금은 계좌 환불이나 동의를 받아 예치금으로 돌려줍니다.
- 5-7 A: 과다 환불은 동의를 받아 예치금에서 차감할 수 있습니다.
- 회원 28-7, L2: 탈퇴 신청 때 환불 계좌로 자동 출금합니다.
- 12-1 A: 적립금은 원장 1개 + 차감 기록 1개이고, 적립 행에 남은 금액을 둡니다.

**예시로 보면**
1. **현금성 출처:** 가상계좌로 산 10만 원짜리를 반품하고 예치금으로 받습니다. 계좌로 출금해도 원래 현금이라 문제가 없습니다.
2. **카드 출처:** 카드로 산 10만 원짜리를 반품하고 예치금으로 받은 뒤 바로 계좌 출금을 요청합니다. 카드 대금이 현금이 됩니다.
3. **섞인 잔액:** 예치금 15만 원 중 10만 원은 카드 출처, 5만 원은 현금 출처입니다. 출금 가능 금액은 얼마일까요?
4. **사용 순서:** 다음 주문에서 예치금 8만 원을 씁니다. 카드 출처부터 써야 출금 가능한 현금 출처가 남아 고객에게 유리합니다.
5. **탈퇴:** 탈퇴 신청 때 남은 예치금을 자동 출금합니다(회원 28-7). 카드 출처분은 어떻게 할까요?

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **적립금(12-1 A)과 같은 구조에 입금 출처를 더합니다.**<br>• 원장 행: 회원, 거래 유형(입금 / 사용 / 사용 취소 / 출금 / 출금 취소 / 이동 / 조정), 금액, 결제·취소·클레임·출금 요청 FK<br>• 입금 행: 남은 금액, 출처 유형(카드성 / 현금성 / 기타)<br>• 출금은 현금성 입금 행에서만 차감합니다. 사용할 때는 카드성부터 차감합니다(예시 3·4).<br>• 탈퇴 때 남은 카드성 예치금은 원 결제 카드로 취소하는 경로를 우선합니다(예시 5) [확인 필요: 법무·PG]. | 예시 2의 카드깡 경로를 DB 단에서 막습니다. 출금 가능 금액이 "현금성 입금 행의 남은 금액 합"으로 바로 나옵니다. 적립금과 같은 구조라 대사(7-4)와 배치를 함께 씁니다. 유효기한이 없을 뿐 컬럼 구성이 같습니다. | 출처 분류 규칙(간편결제 머니, 휴대폰 결제는 어디로?)을 정해야 합니다. 카드성 예치금은 출금되지 않아 고객 문의가 생길 수 있습니다. |
| B | 출처 없이 원장 + 차감 기록만 두고, 모든 예치금을 출금 가능하게 합니다. | 단순하고 고객에게 편합니다. | 예시 2를 막지 못합니다. 여신법 위반 소지를 운영 감시에만 맡기게 됩니다. |
| C | 예치금을 적립금 원장과 한 테이블에 두고 "자산 종류" 컬럼으로 나눕니다. | 테이블이 줄어듭니다. | 선행 15(예치금은 별도 원장)와 다릅니다. 예치금은 회사 부채(고객 돈), 적립금은 마케팅 비용이라 회계 성격이 달라 한 테이블에서 섞이면 대사·보고가 어려워집니다. |

**추천: A.**
- 예치금은 고객의 돈이라 출금을 막을 수는 없지만, 카드로 들어온 돈이 현금으로 나가는 길만은 막아야 합니다. 그러려면 건별 출처가 필요하고, 선행 15의 "건별 차감 기록"이 이미 그 틀을 줍니다.
- 사용 순서를 카드성 먼저로 두면 고객이 출금할 수 있는 금액이 최대로 남습니다.

**A를 고르면 생기는 것 (이름은 후보)**
- `PAY_DEPOSIT_LEDGER`:
  - 컬럼:
    - `DEPOSIT_TRANSACTION_TYPE_CD`
    - `DEPOSIT_AMT`(부호 있음)
    - `DEPOSIT_SOURCE_TYPE_CD`(`CARD_LIKE`, `CASH_LIKE`, `OTHER`)
    - `REMAINING_AMT`(입금 행만)
    - `PAYMENT_ID`, `PAYMENT_CANCEL_ID`, `CLAIM_ID`, `DEPOSIT_WITHDRAWAL_REQUEST_ID`
  - 상태(예정·확정·취소)는 두지 않습니다. 예치금은 들어오는 즉시 확정이기 때문입니다. 다르게 보시면 말씀해 주세요.
- `PAY_DEPOSIT_DEDUCTION`: 적립금 차감 기록과 같은 구조입니다.
- 출처 분류 기준: 출처는 입금을 만든 취소 행의 원 결제 수단에서 정합니다.
  - `CARD_LIKE`: 카드, 원클릭, 간편결제 내부 카드
  - `CASH_LIKE`: 가상계좌, 계좌이체, 간편결제 내부 머니·계좌
  - 휴대폰 결제: `CARD_LIKE`로 분류합니다. 후불 결제라 현금화 위험이 같기 때문입니다.
- 출금 요청 테이블(`PAY_DEPOSIT_WITHDRAWAL_REQUEST`)의 상세는 12-4에서 정합니다.
