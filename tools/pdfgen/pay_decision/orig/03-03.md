## 3-3. 인증·승인 분리와 금액 검증

**무엇을 정하나요?**
국내 PG 결제는 보통 두 단계입니다.
1. **인증:** 고객이 결제창에서 카드 앱 등으로 본인 인증을 합니다.
2. **승인:** 우리 서버가 PG에 승인을 요청해야 돈이 빠져나갑니다.

이 사이에 **금액을 언제 어떻게 검증할지**, 그 결과를 결제 행에 어떻게 남길지 정합니다. 결제창 요청은 고객 브라우저를 거치므로 금액이 바뀔 수 있습니다.

**이미 정한 것**
- 2-1 A: 결제 행을 만들 때 요청 금액을 넣습니다.
- 2-7 A: 승인되면 승인 금액 = 요청 금액(CHECK)입니다. 요청 금액 = 주문 PG 결제 금액은 애플리케이션이 검증합니다.
- 3-1 B: 상태에 `AUTHENTICATED`(인증 완료)가 있고, 실패 사유에 "금액 불일치"가 있습니다.
- 3-2 C: 인증 완료 일시와 승인 일시를 컬럼으로 남깁니다.
- 여신전문금융업법 19조 5항 2호: 실제 매출 금액보다 많이 승인받으면 안 됩니다. 그래서 금액 검증은 보안 장치이면서 법적 의무입니다.

**예시로 보면**
주문 PG 결제 금액은 95,000원입니다.
1. **정상:** 결제창 인증 결과의 금액이 95,000원이고 요청 금액과 같습니다. 그래서 승인을 요청합니다.
2. **변조:** 누군가 브라우저에서 결제창 요청 금액을 9,500원으로 바꿔 인증을 마칩니다.
   - 인증 결과 금액 9,500원 ≠ 요청 금액 95,000원이므로 승인을 요청하지 않고 "실패(금액 불일치)"로 둡니다.
   - 돈은 한 번도 빠져나가지 않습니다.
3. **자동 승인 수단:** 일부 수단(PG 설정에 따라 휴대폰 결제, 일부 간편결제)은 인증과 동시에 승인까지 끝납니다.
   - 승인된 금액이 9,500원이면 이미 돈이 빠져나간 뒤입니다. 즉시 전액 취소하고 "금액 불일치"로 기록해야 합니다.
4. **주문 금액이 그 사이 바뀐 경우:** 결제창이 열린 뒤 다른 탭에서 쿠폰을 바꿨습니다.
   - 주문 3-1 A에 따라 결제 대기 주문의 금액은 고정이고, 바꾸려면 새 주문을 만들어야 합니다.
   - 그래서 승인 직전에 "결제 행 요청 금액 = 주문 PG 결제 금액"을 한 번 더 확인합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **승인 전 검증을 기본으로 합니다.**<br>• 인증 결과를 받으면 인증 금액을 저장하고 상태를 `AUTHENTICATED`로 바꿉니다.<br>• 인증 금액 = 요청 금액 = 주문 PG 결제 금액이 모두 맞을 때만 승인을 요청합니다. 다르면 승인하지 않고 실패로 둡니다.<br>• 자동 승인 수단(예시 3)은 승인 뒤 같은 검증을 하고, 다르면 즉시 전액 취소합니다. 취소 사유는 "금액 불일치 자동 취소"입니다. | 예시 2에서 돈이 빠져나가기 전에 막습니다. 법적 의무(과다 승인 금지)를 구조로 지킵니다. 인증 금액이 남아 변조 시도를 나중에 추적할 수 있습니다. | 인증 금액 컬럼 1개와 자동 취소 흐름이 필요합니다. |
| B | 모든 수단을 승인 뒤에 검증합니다. 다르면 즉시 취소합니다. | 흐름이 하나라 단순합니다. | 예시 2에서도 돈이 한 번 빠져나갔다가 돌아옵니다. 고객 카드 명세에 승인·취소가 남고, 취소가 실패하면 과다 승인 상태가 됩니다. |
| C | 실시간 검증 없이 매일 대사(7-3)에서 찾아냅니다. | 결제 흐름이 가장 빠릅니다. | 하루 동안 잘못된 금액이 승인 상태로 남습니다. 법적 의무를 사후에만 지키게 됩니다. |

**추천: A.**
- 인증과 승인이 나뉜 국내 PG 구조를 그대로 활용하는 방법이고, 결제 금액 변조를 막는 표준 방식입니다.
- 자동 승인 수단이 일부 있어도 같은 검증 규칙에 "승인 뒤 즉시 취소"만 더하면 됩니다.

**A를 고르면 생기는 것 (이름은 후보)**
- `AUTHENTICATED_AMT`: 인증 결과 금액. 인증을 따로 하지 않는 수단은 NULL입니다.
- CHECK: 상태가 `APPROVED`이고 인증 금액이 있으면 인증 금액 = 요청 금액
- 실패 사유 코드 `AMOUNT_MISMATCH`
- 자동 취소 사유 코드 `AMOUNT_MISMATCH_AUTO_CANCEL`: 취소 행(5-1)의 사유 값 목록에 넣습니다.
- 수단별로 인증·승인이 분리되는지는 PG 설정(1-5 A)에 "자동 승인 여부" 컬럼으로 둡니다. 결제 행에는 복사하지 않습니다.
