## 12-1. 적립금 원장과 적립 건별 남은 금액

**무엇을 정하나요?**
선행 15에서 적립금은 "증감 원장 + 적립 건별 차감 기록, 원장 상태는 예정·확정·취소"로 정했습니다. 여기서는 그 원장의 행 구조를 정합니다. 특히 **적립 건마다 남은 금액을 어디서 아는지**를 정합니다. 남은 금액을 알아야 먼저 소멸할 적립금부터 쓰고, 기한이 지난 만큼만 소멸시킬 수 있습니다.

**이미 정한 것**
- 선행 15: 증감 원장 + 적립 건별 차감 기록, 원장 상태는 예정·확정·취소입니다.
- 주문 6-8 A: 결제가 완료되면 원장에 "예정" 행을 만들고, 구매 확정 때 확정합니다.
- 주문 OC-26 A: 적립금 사용은 출처를 둘로 나눠 배분합니다.
  - `POINT_PURCHASE`: 구매 실적으로 적립된 자기적립마일리지(부가가치세법 시행령 61조)
  - `POINT_OTHER`: 이벤트 등
  - 그래서 차감할 때 어느 종류의 적립에서 빠졌는지 알아야 합니다.
- 5-3 A: 반품하면 배분대로 복원합니다.
- 7-4 A: 매일 잔액 = 원장 합계, 배분 = 원장 사용을 대사합니다.
- 회원 29-2 A: 계정 통합 때 원장 이동 거래로 적립금을 옮깁니다.

**예시로 보면**
1. **적립:** 3/1 구매 적립 3,000원(유효기한 1년), 5/1 리뷰 이벤트 2,000원(유효기한 3개월)
2. **사용:** 6/1 주문에서 4,000원 사용. 기한이 빠른 이벤트 2,000원을 먼저, 구매 적립 2,000원을 다음에 씁니다. 배분은 `POINT_OTHER` 2,000원, `POINT_PURCHASE` 2,000원입니다.
3. **반품:** 6/10 반품으로 4,000원 복원. 원래 이벤트 적립의 기한(8/1)이 그대로 살아나야 할까요, 새 기한을 줄까요? 이 정책은 12-3에서 정하고, 여기서는 어느 적립 건에서 빠졌는지가 남아 있어야 합니다.
4. **소멸:** 3/1 적립분 중 남은 1,000원이 다음 해 3/1에 소멸합니다. 남은 금액을 바로 알아야 소멸 배치가 빠릅니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **원장 1개 + 차감 기록 1개, 적립 행에 남은 금액을 둡니다.**<br>• 원장 행: 회원, 거래 유형(적립 / 사용 / 사용 취소 / 소멸 / 적립 취소 / 이동 / 조정), 상태(예정 / 확정 / 취소), 금액(부호 있음), 적립 종류(구매 / 기타), 유효기한, 주문·주문 상품·클레임 FK<br>• 적립 행에만 남은 금액 컬럼을 두고, 차감할 때 함께 줄입니다.<br>• 차감 기록: (차감한 원장 행, 차감된 적립 행, 금액). 사용·소멸 모두 이 기록을 남깁니다. | 예시 2의 "기한 빠른 순 차감"이 남은 금액 > 0인 적립 행을 기한 순으로 읽어 끝납니다. 예시 3에서 어느 적립 건으로 되돌릴지 차감 기록이 알려 줍니다. 예시 4의 소멸 배치가 빠릅니다. 테이블은 2개뿐입니다. | 남은 금액은 차감 기록 합계의 캐시라 어긋날 수 있습니다. 같은 트랜잭션에서 바꾸고, 7-4 대사에 "남은 금액 = 적립 − 차감 합계" 검사를 더합니다. |
| B | A와 같지만 적립 건 테이블을 원장과 따로 둡니다(적립 건 1행 + 그 건의 증감은 원장). | 적립 건의 속성(기한, 종류, 남은 금액)과 증감 기록이 깔끔하게 나뉩니다. | 테이블이 3개가 되고, 적립할 때마다 두 테이블에 씁니다. 규칙 5(테이블 최소화)와 맞지 않습니다. |
| C | 남은 금액 컬럼 없이 차감 기록 합계로 매번 계산합니다. | 캐시가 없어 어긋날 일이 없습니다. | 사용할 때마다 회원의 모든 적립 행과 차감 합계를 계산해야 합니다. 소멸 배치가 무거워집니다. |

**추천: A.**
- 적립금은 기한 순 차감과 소멸이 핵심이라, 적립 건의 남은 금액을 바로 읽을 수 있어야 합니다. 원장의 적립 행 자체가 적립 건 역할을 하면 테이블을 늘리지 않아도 됩니다.
- 캐시가 어긋날 위험은 7-4 A의 매일 대사와 12-5(같은 트랜잭션 갱신)가 막습니다.

**A를 고르면 생기는 것 (이름은 후보)**
- `PAY_POINT_LEDGER`:
  - 컬럼:
    - `POINT_TRANSACTION_TYPE_CD`
    - `POINT_LEDGER_STATUS_CD`(`SCHEDULED`, `CONFIRMED`, `CANCELED`)
    - `POINT_AMT`(부호 있음)
    - `POINT_KIND_CD`(`PURCHASE`, `OTHER`)
    - `EXPIRES_DT`
    - `REMAINING_AMT`(적립 행만)
    - `ORDER_ID`, `ORDER_ITEM_ID`, `CLAIM_ID`, 적립 사유 코드
  - CHECK:
    - 적립 행만 `REMAINING_AMT`, `EXPIRES_DT`가 NOT NULL입니다.
    - `0 <= REMAINING_AMT <= POINT_AMT`
    - 유형별 부호를 검사합니다.
  - 파티션 여부와 보관 기간은 12-4에서 정합니다.
- `PAY_POINT_DEDUCTION`:
  - (`DEDUCTING_LEDGER_ID`, `ACCRUAL_LEDGER_ID`) 복합 PK
  - 금액 > 0
- 함수 기반 인덱스: (회원, 유효기한) 중 남은 금액 > 0이고 확정된 적립 행만 둡니다(차감·소멸 대상).
- 테이블 접두어: 적립금·예치금 원장을 결제 도메인(`PAY`)에 둘지는 이번 결정과 함께 정합니다. 선행 3에 따로 접두어가 없습니다. 다르게 보시면 B·C와 별개로 말씀해 주세요.

<!--ANSWER-->
**사용자:** a

12-1은 A로 메모해 두었습니다. 적립금은 원장 1개와 차감 기록 1개로 둡니다. 적립 행에 남은 금액, 적립 종류, 유효기한을 둡니다. 원장은 결제 도메인(`PAY`)에 둡니다.
