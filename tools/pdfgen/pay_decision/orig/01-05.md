## 1-5. PG 선택(라우팅) 설정

**무엇을 정하나요?**
PG가 여러 곳이라(선행 13), 결제할 때 이 수단을 어느 PG의 어느 상점 ID(MID)로 보낼지 정하는 규칙이 필요합니다. 이 규칙을 어디에 두고, 장애 때 어떻게 바꿀지를 정합니다.

**이미 정한 것**
- 선행 13: 여러 PG + 간편결제 직접 계약. 결제 대행사 코드 + 거래번호 UK. 외부 업체 마스터(`SYS`).
- 1-4 A: 카드, 자사 원클릭, 외부 간편결제, 가상계좌, 계좌이체, 휴대폰 결제를 받습니다.
- 회원 40-1 D: 자사 원클릭은 빌링키를 발급한 PG로만 결제할 수 있습니다.
- 선행 6: 관리자 작업은 관리자 작업 로그에 남깁니다.

**법에서 오는 조건 (여신전문금융업법)**
- 설정에 넣는 MID·가맹점번호는 모두 이 회사 명의여야 합니다. 다른 가맹점 명의로 거래하는 것은 형사처벌 대상입니다(19조 5항 3호, 70조).
- 수단에 따라 PG를 바꿔도 고객이 내는 금액은 같아야 합니다. 특정 PG나 수단을 쓴다고 수수료를 더 받으면 안 됩니다(19조 4항).

**예시로 보면**
1. **평소:**
   - 카드는 PG-가(수수료 2.3%), 가상계좌는 PG-나(건당 300원)로 보냅니다.
   - 휴대폰 결제는 PG-다만 지원합니다.
   - 카카오페이·네이버페이·토스페이는 직접 계약입니다.
2. **장애:** 금요일 밤 PG-가 카드 승인이 실패합니다. 관리자가 카드를 PG-나로 바꾸고, 2시간 뒤 되돌립니다.
3. **기간 설정:** 12월 한 달 동안 PG-나의 무이자 할부 행사가 있어, 그 기간만 카드를 PG-나로 보냅니다.
4. **원클릭 예외:** 회원이 등록한 카드의 빌링키는 PG-가가 발급했습니다. PG-가가 장애면 원클릭은 다른 PG로 돌릴 수 없어 "일시 사용 불가"로 표시해야 합니다.
5. **MID 구분:** 같은 PG-가 안에서도 일반 결제용 MID와 원클릭(빌링) 결제용 MID가 따로 발급됩니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **결제 수단 × PG 설정 테이블**을 두고, 결제할 때 지금 유효한 행 중 우선순위가 가장 높은 것을 씁니다.<br>• 컬럼: 결제 수단 코드, PG 업체 코드, MID, 우선순위, 사용 여부, 적용 시작·종료 일시, 변경 사유<br>• 변경은 관리자 작업 로그에 남깁니다.<br>• 결제 행에는 실제로 쓴 PG 코드와 MID를 남깁니다(2-6). | 예시 2를 배포 없이 관리자 화면에서 바꿉니다. 예시 3은 적용 기간으로, 예시 5는 MID 행으로 표현합니다. 수단 × PG의 M:N이라 규칙 5의 허용 범위입니다. | 테이블 1개가 늘어납니다. "유효한 행이 없으면 그 수단을 화면에서 숨김" 규칙을 애플리케이션이 지켜야 합니다. |
| B | 애플리케이션 설정 파일에 둡니다. | 테이블이 없습니다. | 예시 2에서 바꾸려면 배포나 재시작이 필요합니다. 언제 누가 바꿨는지가 DB에 없어 장애 기간의 결제를 설명하기 어렵습니다. |
| C | `CMM_CODE`의 결제 수단 코드 행 `ATTR1`~`ATTR5`에 PG 코드와 MID를 넣습니다. | 테이블이 늘지 않습니다. | 수단 하나에 PG 하나만 담겨 예시 3(기간)과 우선순위를 표현할 수 없습니다. 코드 테이블이 운영 설정을 품게 됩니다. |

**추천: A.**
- PG를 여럿 둔 이유가 장애 대비와 수수료 최적화이므로, 바꾸는 일이 운영 화면에서 바로 되어야 합니다.
- MID를 한곳에서 관리하면 "모든 MID가 이 회사 명의인지"(19조 5항 3호)를 설정 목록 하나로 점검할 수 있습니다.
- 예시 4(원클릭)는 이 테이블로 PG를 바꾸지 않습니다. 저장 결제수단을 발급한 PG로만 결제하고, 그 PG의 사용 여부가 N이면 원클릭을 숨깁니다. 이 규칙을 설정 테이블 설명에 적습니다.

**A를 고르면 생기는 것 (이름은 후보)**
- 결제 수단 PG 설정 테이블:
  - 컬럼: 결제 수단 코드, PG 업체 코드, MID, MID 용도(일반 / 빌링), 우선순위, 사용 여부, 적용 시작·종료 일시, 변경 사유
  - UK: (수단, PG, MID, 적용 시작 일시)
  - 마스터·설정이라 논리 삭제를 씁니다(선행 4).
- PG 업체 코드는 외부 업체 마스터(`SYS`)의 업체 코드를 씁니다. 회원 저장 결제수단의 결제 대행사 코드도 같은 값 목록입니다.
- 1-7에서 카드사 직가맹을 고르면, 이 테이블에 "정산 방식(PG 정산 / 카드사 직정산)" 컬럼이 더해집니다.
- 수수료율은 이 테이블에 두지 않습니다. 계약 조건이라 정산 도메인이 다룹니다(1-6).
