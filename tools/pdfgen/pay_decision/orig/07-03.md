## 7-3. PG 거래 대사와 불일치 유형

**무엇을 정하나요?**
PG가 매일 주는 거래 내역(승인·취소)과 우리 결제·취소 행을 맞춰 볼 때, 무엇을 저장하고 불일치를 어떻게 분류·해결할지 정합니다. 입금(정산) 대사는 정산 도메인이 맡습니다(1-6 A).

**이미 정한 것**
- 1-6 A: 거래 대사는 결제 도메인, 정산 대사·수수료는 정산 도메인이 맡습니다.
- 선행 11: 외부 대사는 애플리케이션 배치로 돌립니다. 배치 실행 이력은 `BAT` 테이블에 둡니다.
- 대사에 맡겨 둔 것:
  - 3-7·4-2: 결과 불명, 웹훅 유실
  - 5-7 A: PG에만 있는 취소를 우리 취소 행으로 들여오기(`PG_CONSOLE_CANCEL`)
  - 6-4 A, 6-8 A: 현금영수증 금액, 과세·면세 잔액 맞추기
  - 2-7 A: 취소 행 합계 = 취소 누계

**예시로 보면**
11월 25일 PG-가 거래 파일은 13,000건, 승인 13억 원, 취소 4,200만 원입니다.
1. **PG에만 있음:** 승인 1건이 우리 DB에서는 `FAILED`입니다. 만료 뒤 승인(3-8)이거나 결과 불명 처리가 잘못된 경우입니다.
2. **우리에만 있음:** 우리 DB에서는 `APPROVED`인데 PG 파일에 없습니다. 23:59:58 승인이라 PG가 다음 날 파일에 넣었을 수 있습니다(날짜 경계).
3. **금액 다름:** 부분 취소 금액이 우리 30,000원, PG 3,000원입니다.
4. **상태 다름:** PG는 취소, 우리는 승인입니다. PG 관리자 화면에서 직접 취소한 경우입니다(5-7).
5. **내부 불일치:** 취소 행 합계와 결제 행 취소 누계가 다릅니다. PG와 상관없이 우리 DB 안의 문제입니다.
6. **해결 추적:** 불일치 12건 중 10건은 다음 날 저절로 맞고(날짜 경계), 2건은 운영자가 처리합니다. 누가 언제 어떻게 처리했는지가 남아야 합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | PG 거래 파일의 모든 행을 적재 테이블에 저장하고 대사합니다. 불일치 테이블을 따로 둡니다. | PG가 말한 값을 DB에서 언제든 다시 봅니다. | 하루 수만 행이 중복 저장됩니다(우리 결제 행과 거의 같은 내용). 적재 테이블의 보관·파티션 관리가 필요합니다. |
| **B** | **실행 테이블 + 불일치 테이블**만 둡니다.<br>• 대사 실행 1행(PG × 거래일): 파일명, 파일 해시, 양쪽 건수·금액 합계, 상태<br>• 불일치 1행: 유형, 결제·취소 ID, PG 거래번호, 우리 값과 PG 값(금액·상태), 해결 상태(미해결 / 자동 해소 / 수동 해소), 해결 방법, 해결 일시, 담당자<br>• 원본 파일은 파일 보관소에 두고 해시로 확인합니다. | 문제가 된 건만 저장해 작습니다. 불일치 행에 양쪽 값이 있어 예시 1~4를 바로 처리합니다. 예시 6의 추적이 됩니다. 날짜 경계(예시 2)는 다음 날 실행에서 자동 해소됩니다. | PG 파일 전체를 다시 보려면 보관소의 원본 파일을 열어야 합니다. |
| C | 실행 요약(건수·금액 합계)만 저장합니다. | 가장 작습니다. | 어느 거래가 틀렸는지 남지 않아 예시 1~4를 처리할 수 없습니다. |

**추천: B.**
- 대사의 목적은 "다른 것을 찾아 고치는 것"이라 다른 것만 기록하면 됩니다. 일치하는 수만 건은 결제 행이 이미 담고 있습니다.
- 파일 해시를 남기면 원본 파일이 바뀌지 않았음을 증명할 수 있어, 파일 전체를 DB에 넣지 않아도 근거가 됩니다.

**B를 고르면 생기는 것 (이름은 후보)**
- `PAY_RECONCILIATION_RUN`: UK(PG 업체 코드, 거래일, 실행 차수). 배치 실행 이력(`BAT`)과는 별개의 업무 기록입니다.
- `PAY_RECONCILIATION_MISMATCH`: 실행 FK, 결제·취소 ID는 FK 없이 인덱스만 둡니다(파티션 제거 영향 피함).
- 불일치 유형 코드:
  - `PG_ONLY`, `OURS_ONLY`, `AMOUNT_DIFF`, `STATUS_DIFF`, `TAX_SPLIT_DIFF`
  - `INTERNAL_SUM_DIFF`(우리 내부: 취소 합계 ≠ 누계)
  - `CASH_RECEIPT_DIFF`(6-4)
- 해결 방법 코드: 날짜 경계 자동 해소, 결제 행 조회 반영, PG 취소 들여오기(5-7), 운영자 조정
- 미해결 상태로 N일이 지나면 운영자에게 알립니다. N은 정책값입니다.
