## 2-4. 수단별 상세 정보 저장 방식

**무엇을 정하나요?**
결제 수단마다 남겨야 할 정보가 다릅니다. 이 정보를 한 테이블의 컬럼으로 둘지, 수단별 테이블로 나눌지, JSON으로 담을지를 정합니다.
- **카드:** 카드사, 매입사, 마스킹 카드번호, 신용·체크 구분, 할부 개월, 무이자 여부, 승인번호
- **가상계좌:** 은행, 계좌번호, 입금자명, 입금 기한, 입금 일시
- **계좌이체:** 은행, 마스킹 계좌번호
- **간편결제:** 간편결제사, 내부 결제 수단(카드 / 머니), 내부 카드사
- **휴대폰 결제:** 통신사, 휴대폰 번호

**이미 정한 것**
- 규칙 5: 테이블보다 컬럼을 늘립니다. 1:1 테이블은 예외로 정한 것만 있습니다.
- 선행 5: PG에서 받은 마스킹 값(카드번호 등)은 그대로 저장합니다. 휴대폰 번호는 암호화 대상입니다.
- 선행 2: 21c 네이티브 `JSON` 타입을 쓸 수 있습니다.
- 1-4 A: 수단은 6개입니다(카드, 원클릭, 간편결제, 가상계좌, 계좌이체, 휴대폰).
- 2-3 A: 결제 테이블은 PG 결제만 담습니다.

**예시로 보면**
1. **카드 할부:** 신한카드 3개월 무이자로 결제합니다. 저장 값은 `ISSUER=SHINHAN`, `CARD_NO=4518-12**-****-3456`, `INSTALLMENT=3`, `INTEREST_FREE=Y`, 승인번호 `30012345`입니다.
2. **CS 조회:** 고객이 "체크카드로 냈는데 환불이 언제 들어오나요?"라고 묻습니다. 상담원이 신용·체크 구분과 카드사로 환불 소요일을 안내합니다.
3. **통계:** 이번 달 카드사별 무이자 할부 결제액을 집계합니다. 무이자 분담 비용은 정산 도메인이 계산합니다(10-2).
4. **가상계좌 입금:** 우리은행 가상계좌 `1002-***-1234`에 입금 기한 내일 23:59까지 입금해야 합니다. 입금되면 입금 일시와 입금자명이 채워집니다.
5. **카카오페이 내 카드:** 카카오페이로 결제했는데 내부 수단은 현대카드 할부입니다. 간편결제사와 카드 정보가 함께 필요합니다(2-5).

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **결제 테이블 하나에 수단별 컬럼을 모두 둡니다.** 해당하지 않는 수단에서는 NULL입니다. "수단이 카드면 카드사 NOT NULL" 같은 CHECK를 수단별로 겁니다. PG 응답 원문은 PG 연동 로그에 둡니다(7-1). | 규칙 5와 맞습니다. 예시 2·3을 조인 없이 조회하고 인덱스를 걸 수 있습니다. 예시 5처럼 간편결제 + 카드 정보를 한 행에 담습니다. | 컬럼이 20개 이상 늘고, 한 행에서 대부분이 NULL입니다(NULL은 Oracle에서 거의 공간을 쓰지 않습니다). |
| B | 공통 결제 테이블 + 수단별 1:1 상세 테이블(카드, 가상계좌, 휴대폰 등)을 둡니다. | 테이블마다 컬럼이 깔끔하고 NOT NULL을 바로 겁니다. | 규칙 5의 예외가 3~5개 늘어납니다. 예시 5는 간편결제 행과 카드 상세 행을 둘 다 만들어야 합니다. 조회마다 조인이 필요합니다. |
| C | 공통 컬럼 + 수단별 상세를 `JSON` 컬럼 하나에 담습니다. | 컬럼이 가장 적습니다. 수단이 늘어도 구조를 바꾸지 않습니다. | 예시 3의 집계·인덱스가 어렵습니다. 값 목록(카드사 코드)과 CHECK를 걸 수 없습니다. 암호화 대상(휴대폰 번호)이 JSON 안에 섞입니다. |

**추천: A.**
- 카드사·할부·신용/체크는 CS, 통계, 정산, 환불 소요일 안내에 매일 쓰는 값이라 컬럼이어야 합니다.
- 수단이 6개로 정해져 있어 컬럼이 무한히 늘지 않습니다. 원문 전체는 PG 로그가 맡으므로 "혹시 필요할 값"까지 컬럼으로 만들 필요는 없습니다.

**A를 고르면 생기는 것 (이름은 후보, 확정은 컬럼 검토 때)**
- 카드 그룹: 카드사 코드, 매입사 코드, 마스킹 카드번호, 카드 종류(신용 / 체크 / 기프트), 할부 개월, 무이자 여부, 승인번호
- 가상계좌 그룹: 은행 코드, 계좌번호, 입금 기한, 입금 일시, 입금자명. 암호화 여부는 8-3에서 정합니다.
- 계좌이체 그룹: 은행 코드, 마스킹 계좌번호
- 간편결제 그룹: 간편결제사 코드, 내부 결제 수단 코드. 내부 카드 정보는 카드 그룹 컬럼을 함께 씁니다(2-5).
- 휴대폰 그룹: 통신사 코드, 휴대폰 번호 암호문(선행 5), 마스킹 번호
- 수단별 CHECK: 수단 코드에 따라 그 그룹의 필수 컬럼이 NOT NULL인지 검사합니다.
- 새 코드 그룹: 카드사, 은행, 통신사, 간편결제사. 카드사·은행 코드는 PG마다 값이 달라 PG 코드 대응표가 필요합니다. 어디에 둘지는 컬럼 검토 때 여쭙겠습니다.
