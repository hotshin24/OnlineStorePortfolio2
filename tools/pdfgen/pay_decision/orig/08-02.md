## 8-2. 빌링키(원클릭) 결제와 저장 결제수단 연결

**무엇을 정하나요?**
원클릭 결제 행이 회원의 저장 결제수단(`MBR_SAVED_PAYMENT_METHOD`)을 어떻게 가리킬지 정합니다. 빌링키를 어디서 어떻게 꺼내 쓰는지도 정합니다.

**이미 정한 것**
- 회원 40-1 D, 40-2 B: 빌링키는 암호화해 저장 결제수단 테이블에 둡니다. 원클릭은 빌링키를 발급한 PG로만 결제합니다.
- 회원 41-1 D: 결제할 때 6자리 결제 비밀번호로 확인합니다.
- 회원 47-1 A: 저장 결제수단은 삭제할 때 PG 빌링키를 삭제하고 **행을 물리 삭제**합니다.
  - 회원 테이블의 "최근 사용 결제수단 ID"는 FK에 `ON DELETE SET NULL`을 걸었습니다(C-56).
- 1-4 A: CHECK "수단이 원클릭이면 저장 결제수단 ID NOT NULL"을 걸기로 했습니다.
- 2-6 A: 원클릭이면 MID 용도는 빌링입니다.
- 8-1 A: 결제 행은 저장 결제수단의 마스킹 카드번호를 복사합니다.

**예시로 보면**
1. **결제:** 회원이 등록 카드 `451842******3456`으로 결제 비밀번호를 넣고 결제합니다. 결제 행은 저장 결제수단 #77을 가리킵니다.
2. **카드 삭제:** 석 달 뒤 회원이 그 카드를 삭제합니다. 47-1 A에 따라 #77 행이 물리 삭제됩니다.
   - 결제 행이 FK로 #77을 가리키고 있으면 삭제가 막히거나(FK만 건 경우), 결제 행의 값이 NULL로 바뀝니다(`ON DELETE SET NULL`).
   - NULL로 바뀌면 1-4의 CHECK("원클릭이면 NOT NULL")에 걸려 삭제 자체가 실패합니다.
3. **분쟁:** 1년 뒤 "이 결제는 어느 등록 카드로 했나"를 물으면, 결제 행에 남은 ID와 마스킹 번호로 답합니다.
4. **빌링키 노출:** 결제 행이나 로그에 빌링키가 복사되면, 빌링키 하나로 결제할 수 있는 값이 여러 곳에 퍼집니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 결제 행에 저장 결제수단 FK를 `ON DELETE SET NULL`로 겁니다(회원 C-56과 같은 방식). 1-4의 CHECK는 결제 행을 만들 때 애플리케이션이 검사하는 것으로 바꿉니다. | 회원 도메인과 같은 방식입니다. | 예시 2에서 큰 결제 테이블의 여러 행이 UPDATE되고, 이 FK 컬럼에 인덱스가 필요합니다. 예시 3의 "어느 등록 카드"가 사라집니다. 1-4의 CHECK를 DB에서 지킬 수 없습니다. |
| **B** | **결제 행에는 저장 결제수단 ID를 FK 없이 값으로 남깁니다.**<br>• 결제 순간의 카드 정보(마스킹 번호, 카드사)는 이미 복사돼 있습니다(8-1 A).<br>• 빌링키는 결제 행·로그 어디에도 복사하지 않습니다. 결제 서비스가 결제 직전에 저장 결제수단에서 읽어 메모리에서만 복호화하고, PG로 보낸 뒤 버립니다.<br>• 결제 비밀번호 확인 결과는 9-5(본인 확인 방식 기록)에 남깁니다. | 예시 2의 삭제가 결제 테이블에 영향을 주지 않습니다. 1-4의 CHECK를 DB에서 그대로 지킵니다. 예시 3에 답할 수 있습니다. 빌링키가 한 곳(회원 도메인 암호문)에만 있습니다. | 삭제된 저장 결제수단 ID를 가리키는 값이 남습니다. 이 값은 FK가 아니라 기록용 값이라고 컬럼 설명에 적어야 합니다. |
| C | FK를 걸고 `ON DELETE` 동작을 주지 않습니다. 결제가 있는 저장 결제수단은 삭제할 수 없게 됩니다. | 참조 정합성이 가장 강합니다. | 회원 47-1 A(물리 삭제)와 충돌합니다. 회원이 카드를 지울 수 없게 됩니다. |

**추천: B.**
- 결제 행은 "그때 무엇으로 결제했나"를 남기는 거래 기록이라, 저장 결제수단이 지워져도 그 값이 그대로 있어야 합니다. 주문 도메인이 상품 정보를 스냅샷으로 남긴 것과 같은 원리입니다.
- 빌링키를 한 곳에만 두는 것이 가장 큰 보호입니다.

**B를 고르면 생기는 것 (이름은 후보)**
- 결제 행 컬럼: `SAVED_PAYMENT_METHOD_ID`
  - FK 없음, 기록용입니다.
  - 일반 인덱스를 두어 "이 등록 카드의 결제 내역" 조회에 씁니다.
- CHECK: 수단이 `ONE_CLICK`이면 `SAVED_PAYMENT_METHOD_ID`가 NOT NULL (1-4 A 그대로)
- 빌링키는 결제 행, PG 호출 요약 로그(7-1 C), 외부 로그 원문 어디에도 남기지 않습니다. 외부 로그의 가림 규칙은 8-4에서 정합니다.
- 회원 도메인을 다시 볼 때 확인할 것(지금은 고치지 않음): 회원 테이블에 현금영수증 기본 용도와 식별번호 암호문이 있습니다. 6-1 C의 결제 행 신청 정보를 이 기본값에서 채우는 흐름을 맞춥니다.

<!--ANSWER-->
**사용자:** b

8-2는 B로 메모해 두었습니다. 결제 행에는 저장 결제수단 ID를 FK 없이 기록용 값으로만 남깁니다. 빌링키는 결제 직전에 메모리에서만 복호화하고, 어디에도 복사하지 않습니다.
