## 7-7. 주요 시각 컬럼

**무엇을 정하나요?**
결제 완료, 출고, 배송 완료 같은 **중요한 시각을 주문 행에 컬럼으로 따로 둘지**입니다. 상태 이력(7-3 C)에서 매번 찾을지와 비교해 정합니다.

**법은 무엇을 요구하나요?**
전자상거래법 17조 5항에 따라, 계약 체결 사실과 시기, 공급 사실과 시기에 다툼이 있으면 **회사가 증명**해야 합니다. 그래서 주문한 때와 상품이 도착한 때는 반드시 정확히 남아 있어야 합니다.

**어디에 쓰이나요?**
- **청약철회 기간 계산:** 서면 교부일 또는 배송 완료일부터 7일
- **공급 기한 감시:** 결제 완료일부터 3영업일 (8-4)
- **자동 구매 확정:** 배송 완료 + N일 (7-5)
- **정산 기준일:** 결제 완료, 배송 완료, 구매 확정 중 하나. 무엇을 기준으로 할지는 정산 도메인에서 정합니다.
- **관리자 검색:** "어제 결제 완료된 주문", "지난주 배송 완료된 상품"

**예시로 보면**
관리자가 "11월 1일~7일에 배송 완료된 상품"을 찾습니다.
- 컬럼이 있으면: 배송 완료 일시에 인덱스를 걸어 바로 찾습니다.
- 컬럼이 없으면: 상태 이력에서 "다음 상태 = 배송 완료"인 행을 찾아 주문 상품과 조인합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 주요 시각을 컬럼으로 둠. 상태가 바뀌는 같은 트랜잭션에서 채움 | 기간 검색과 기한 계산이 빠름. 증명에 필요한 시각이 주문과 함께 5년 남음 | 상태 이력과 같은 시각이 두 곳에 있음 |
| B | 컬럼을 두지 않고 상태 이력에서 찾음 | 중복이 없음 | 자주 쓰는 검색마다 이력을 조인함. 상태가 아닌 시각(서면 교부, 출고 요청)은 이력에 없음 |
| C | 법적 증명에 필요한 시각만 컬럼으로 두고 나머지는 이력에서 찾음 | 컬럼이 적음 | 어느 것이 "법적 필수"인지 기준이 애매함. 정산 기준일이 정해지지 않아 무엇을 뺄지 정할 수 없음 |

**추천: A.**

**A로 둘 시각 (지금까지 정한 것 포함)**

| 위치 | 시각 | 관련 패턴 |
|---|---|---|
| 주문 | 주문 일시 (결제 대기 생성) | |
| 주문 | 주문 내용 확인 일시 | 3-7 |
| 주문 | 결제 완료 일시 | |
| 주문 | 계약 서면 교부 일시 | 3-9 |
| 주문 | 결제 만료 일시 | 3-4 |
| 주문 상품 | 출고 요청 일시 | 1-5 |
| 주문 상품 | 출고 일시 | |
| 주문 상품 | 배송 완료 일시 | 1-7 |
| 주문 상품 | 구매 확정 일시 | 7-5 |
| 주문 상품 | 끝 상태 일시 (취소 완료·반품 완료) | 7-2 |

- 출고·배송은 상품마다 다르므로 주문 상품에 둡니다.
- 결제는 주문 전체에 한 번이므로 주문에 둡니다.
- 인덱스는 10-5(조회 패턴별 인덱스)에서 정합니다.

**A를 고르면 생기는 것**
- 표의 시각 컬럼 (`_AT`, `TIMESTAMP`). 이미 다른 패턴에서 정한 것은 중복이 아니라 같은 컬럼입니다.
