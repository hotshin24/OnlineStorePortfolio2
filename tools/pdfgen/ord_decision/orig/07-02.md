## 7-2. 주문 상태와 클레임 상태의 경계

**무엇을 정하나요?**
"취소 요청", "반품 진행 중", "취소 완료" 같은 **클레임 관련 상태를 주문 상품 상태에 넣을지**입니다.

**이미 정한 것**
- 1-1 A: 결제 뒤의 취소·반품·교환은 클레임 도메인이 맡습니다. 클레임마다 자기 상태(접수, 회수 중, 검수, 환불 완료 등)를 가집니다.
- 1-6 A: 주문 상품에는 취소 수량과 반품 수량만 반영합니다.

**예시로 보면**
양말 3켤레(주문 상품 1행) 중 1켤레를 반품 신청했습니다.
- 클레임 쪽: 반품 1건, 상태 "회수 중"
- 주문 상품 쪽: 상태는 무엇이어야 할까요? 2켤레는 정상이고 1켤레는 반품 중입니다.

다른 경우: 셔츠 1장(주문 상품 1행)을 출고 전에 전부 취소했습니다. 이 행은 다시는 출고되면 안 됩니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 주문 상품 상태에 클레임 진행 상태까지 넣음 (취소 요청, 반품 회수 중, 반품 완료 등) | 주문만 보면 모든 진행이 보임 | 같은 진행을 주문과 클레임 두 곳에서 관리해 어긋남. 양말 예시처럼 일부만 반품 중이면 상태 하나로 표현할 수 없음 |
| B | 주문 상품 상태는 정상 흐름만 둠 (결제 대기 → 결제 완료 → 출고 → 배송 완료 → 구매 확정). 클레임은 수량으로만 반영함 | 두 도메인의 상태가 겹치지 않음 | 전부 취소된 셔츠도 상태가 "결제 완료"로 남음. "취소된 상품"을 찾으려면 수량을 비교해야 함 |
| **C** | B에 더해, 수량이 모두 소진되면 끝 상태로 바꿈: 취소 수량 = 주문 수량이면 "취소 완료", 반품까지 합쳐 다 소진되면 "반품 완료". 진행 중인 클레임 상태는 넣지 않음 | 진행 상태는 클레임 한 곳에만 있음. 끝난 결과는 주문 상품 상태로 바로 보여 검색·집계가 쉬움 | 끝 상태로 바꾸는 규칙이 하나 생김 |

**추천: C.** 앞의 정리에서는 B를 추천했는데, 다시 보니 C가 낫습니다.
- B로는 "출고하면 안 되는 상품"을 상태만 보고 거를 수 없습니다. 출고 요청(1-5), 관리자 목록, 매출 집계가 모두 수량 비교를 해야 합니다.
- C의 끝 상태는 수량에서 기계적으로 정해지는 값입니다. 클레임 진행과 어긋날 일이 없습니다. 1-6 A의 수량 반영과 같은 트랜잭션에서 바꿉니다.
- 진행 중 표시("반품 회수 중")는 고객 화면에서 클레임을 함께 조회해 보여 줍니다. 진행 중인 클레임은 소수라 부담이 작습니다.

**C를 고르면 생기는 것**
- 주문 상품 상태 값에 "취소 완료", "반품 완료" 추가
- 규칙: 취소 수량 + 반품 수량 = 주문 수량이 되면 끝 상태로 바꿈. 수량이 섞이면(1 취소 + 2 반품) "반품 완료"로 둠
- 교환은 수량이 줄지 않으므로 상태를 바꾸지 않음 (4-5 A)
