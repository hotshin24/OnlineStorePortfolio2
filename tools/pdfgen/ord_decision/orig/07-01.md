## 7-1. 상태를 두는 단위

**무엇을 정하나요?**
상태 컬럼을 **주문(헤더)에 둘지, 주문 상품(행)에 둘지, 둘 다 둘지**입니다.

**왜 행에도 상태가 필요한가요?**
한 주문 안에서 상품마다 진행이 다를 수 있습니다.
- 티셔츠와 바지는 출고되었는데, 예약 상품인 코트는 3주 뒤에 출고됩니다 (1-5 A).
- 셔츠는 배송 완료, 바지는 배송 중입니다.
- 셔츠는 구매 확정, 바지는 반품 진행 중입니다.

**예시로 보면**

| 주문 상품 | 상태 |
|---|---|
| 티셔츠 | 배송 완료 |
| 바지 | 배송 완료 |
| 코트 | 결제 완료 (출고 대기) |

고객의 주문 목록에는 이 주문이 한 줄로 보이고, 상태도 하나("부분 배송 완료")가 보여야 합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 둘 다 둠. 주문 상품 상태가 원천이고, 주문 상태는 그 요약임. 상품 상태가 바뀌는 같은 트랜잭션에서 주문 상태도 다시 계산해 저장함 | 상품별 진행을 그대로 표현함. 주문 목록은 헤더 상태만 읽어 빠름 | 요약 규칙을 정해야 함. 두 곳을 함께 고쳐야 함 |
| B | 주문 상품에만 둠. 주문 상태는 조회할 때 계산함 | 값이 한 곳에만 있음 | 주문 목록과 관리자 검색("출고 대기 주문")마다 상품 행을 집계함 |
| C | 주문에만 둠 | 가장 단순함 | 예시처럼 상품마다 다른 진행을 표현할 수 없음 |

**추천: A.**
- 1-6 A, 1-7 A와 같은 방식입니다. 원천은 하나로 두고, 자주 읽는 쪽에는 같은 트랜잭션에서 결과를 반영합니다.

**요약 규칙의 예**
- 모든 상품이 같은 상태면 그 상태입니다.
- 섞여 있으면 "부분 출고", "부분 배송 완료"처럼 둡니다.
- 정확한 상태 목록과 요약 규칙은 7-2(클레임과의 경계)를 정한 뒤 결정 단계에서 코드 값 목록으로 드리겠습니다.

**4-6 B (선물하기)와의 관계**
"수락 대기", "기한 만료", "거절"은 주문 전체에 걸리는 상태입니다. 그래서 주문 상태와 주문 상품 상태에 모두 들어갑니다.

**A를 고르면 생기는 것**
- 주문: 주문 상태 코드 (CHECK)
- 주문 상품: 주문 상품 상태 코드 (CHECK)
- 상태 코드 그룹 2개 (값 목록은 결정 단계에서)
