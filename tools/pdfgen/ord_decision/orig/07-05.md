## 7-5. 구매 확정

**무엇을 정하나요?**
"이 상품은 거래가 끝났다"고 보는 **구매 확정을 어떤 단위로, 언제, 어떻게 할지**입니다.

**구매 확정이 쓰이는 곳**
- **적립금 확정:** "예정" 적립금이 "확정"되어 쓸 수 있게 됨 (6-8)
- **리뷰 작성:** 리뷰 작성 조건으로 씀
- **정산:** 정산 기준일 후보 (7-7)
- **공동현관 출입 방법 파기:** 모든 상품이 확정되면 지움 (5-8 B)

**법은 무엇을 요구하나요?**
- **전자상거래법 17조 1항:** 단순 변심 청약철회는 상품을 받은 날부터 7일입니다. 자동 구매 확정을 7일보다 빨리 하면, 고객이 철회할 수 있는 기간에 적립금이 확정됩니다.
- **17조 3항:** 상품이 표시·광고와 다르면 받은 날부터 **3개월**(안 날부터 30일) 안에 철회할 수 있습니다. 그래서 구매 확정을 했다고 반품을 막으면 안 됩니다.

**예시로 보면**
1. 11월 1일 배송 완료
2. 고객이 구매 확정을 누르지 않아 11월 8일 배치가 자동 확정함. 적립금 1,374원 확정
3. 12월 10일 고객이 "사진과 색이 완전히 다르다"며 반품 신청

3은 법정 기간 안이라 받아야 합니다. 그러면 이미 확정된 적립금 1,374원은 회수합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 주문 상품마다 구매 확정 일시를 둠. 고객이 직접 확정하거나, 배송 완료 + N일(정책값, 7일 이상)에 배치가 자동 확정함. 확정 뒤에도 17조 3항 반품은 클레임에서 받고, 확정된 적립금은 회수함 | 상품별로 적립금·리뷰·정산이 움직임. 법정 철회권을 막지 않음 | 확정 뒤 반품 때 적립금 회수 규칙이 필요함 (적립금 원장 쪽) |
| B | 주문 전체 단위로 확정함 | 단순함 | 예약 상품처럼 늦게 오는 상품이 있으면 먼저 받은 상품도 확정이 늦어짐 |
| C | 구매 확정 없이 배송 완료로 대신함 | 상태가 하나 적음 | 철회 기간 안에 적립금이 확정됨. 정산 기준일이 애매해짐 |

**추천: A.**
- 정책값 N을 7보다 작게 넣지 않도록, 정책값 설명과 애플리케이션 검사로 막습니다. 정책값이라 DB CHECK는 걸 수 없습니다.
- 확정된 상품에 클레임이 들어와도 상태는 7-2 C 규칙을 따릅니다. 수량이 모두 반품되면 "반품 완료"가 됩니다.

**A를 고르면 생기는 것**
- 주문 상품: 구매 확정 일시, 구매 확정 방식 코드 (고객 / 자동 / 관리자)
- 주문 상품 상태 값 "구매 확정"
- 공통코드 정책값 1개 (자동 확정 일수)
