## 6-2. 주문 금액 불변 원칙

**무엇을 정하나요?**
결제가 끝난 뒤 **주문과 주문 상품의 금액 컬럼을 고칠 수 있게 할지**입니다.

**예시로 보면**
6-1의 주문(결제 117,000원)에서 바지를 반품해 71,200원을 돌려줬습니다. 이제 이 주문의 "결제 금액"은 얼마로 보여야 할까요?
- 처음 결제한 117,000원
- 반품 뒤 남은 45,800원

둘 다 필요한 값입니다. 문제는 **어느 값을 주문 행에 저장하고, 다른 값은 어떻게 구하느냐**입니다.

**관련된 확정 결정**
- 선행 4: 거래·원장은 고치거나 지우지 않고, 반대 금액 행으로 정정합니다.
- 1-1 A: 취소·반품의 금액은 클레임 도메인이 기록합니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 결제가 끝나면 주문·주문 상품의 금액을 바꾸지 않음. 취소·반품·환불은 클레임 도메인의 금액 행으로만 기록함. "현재 유효 금액"은 주문 금액에서 클레임 금액을 빼서 구함 | PG 결제 금액과 언제나 맞음. 계약 서면(3-9)을 주문 데이터로 다시 만들 수 있음. 선행 4의 원칙과 같음 | 현재 유효 금액을 보려면 클레임 금액을 함께 조회해야 함 |
| B | 부분 취소·반품 때마다 주문 금액을 새 값으로 고침 | 주문만 보면 현재 금액이 나옴 | 처음 결제 금액이 사라져 PG 대사 기준이 흔들림. 계약 서면을 다시 만들 수 없음. 선행 4와 맞지 않음 |
| C | 원래 금액과 현재 금액을 둘 다 둠. 현재 금액은 클레임 때 갱신함 | 둘 다 바로 보임 | 현재 금액이 클레임 금액의 합계라 어긋날 수 있음. 금액 컬럼이 두 배가 됨 |

**추천: A.**
- 현재 유효 금액은 고객 화면과 상담에서 자주 보지만, 클레임은 주문의 일부에서만 생기므로 조회 부담이 작습니다.
- 수량은 이미 1-6 A에서 주문 상품에 취소·반품 수량을 반영하기로 했습니다. 수량은 바뀌어도 금액은 바뀌지 않는 이유는 다음과 같습니다.
  - 수량은 "더 반품할 수 있는지" 막는 데 매번 쓰입니다.
  - 금액은 클레임 행에 이미 정확하게 있습니다.
- 결제 전(결제 대기 상태)에는 쿠폰을 바꾸거나 다시 계산할 수 있으므로 금액을 고칠 수 있습니다. "불변"은 결제 완료 이후에만 적용합니다.

**A를 고르면 생기는 것**
- 새 컬럼은 없습니다.
- 규칙: 결제 완료 이후 금액 UPDATE 금지. 트리거를 쓰지 않으므로 애플리케이션 공통 코드와 검증 SQL로 지킵니다. 금액 UPDATE는 데이터 변경 감사 로그(선행 6)에도 남습니다.
