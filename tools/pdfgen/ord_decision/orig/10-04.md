## 10-4. 고빈도 시퀀스 대상

**무엇을 정하나요?**
주문 도메인 테이블 중 **어느 시퀀스를 "고빈도"(CACHE 100)로 둘지**입니다.

**이미 정한 것**
선행 1 [확정]:
- 테이블마다 시퀀스 `SEQ_{테이블}`을 둡니다.
- CACHE는 고빈도 100, 저빈도 20입니다.
- 어느 테이블이 고빈도인지는 도메인에서 정합니다.

**CACHE란?**
Oracle이 시퀀스 번호를 미리 몇 개씩 메모리에 받아 두는 개수입니다.
- 크면 번호를 받을 때 기다림이 줄어듭니다. 발매처럼 주문이 몰릴 때 중요합니다.
- 대신 DB를 재시작하면 받아 둔 번호가 버려져 번호에 빈 곳이 생깁니다.
- 대리 PK는 번호에 빈 곳이 있어도 문제가 없습니다. 주문번호(3-2 B)는 시퀀스가 아니므로 영향이 없습니다.

**지금까지 정한 주문 도메인 테이블**

| 테이블 | 시퀀스 | 행 수 (주문 1건당) |
|---|---|---|
| 장바구니 | 있음 | 담을 때마다 |
| 주문 | 있음 | 1 |
| 주문 상품 | 있음 | 1~3 |
| 할인 배분 | 있음 | 주문 상품 × 사용 출처 수 |
| 주문 상품 상태 이력 | 있음 | 주문 상품 × 상태 변경 수 |
| 주문 사은품 | 있음 | 사은품 행사 주문만 |
| 주문 유입 정보 | 없음 (주문 ID 공유 PK, 3-6 B) | 1 |

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 장바구니, 주문, 주문 상품, 할인 배분, 상태 이력은 CACHE 100. 주문 사은품은 CACHE 20 | 발매 순간 몰리는 테이블은 모두 고빈도로 둠. 사은품은 행사 주문에만 생겨 저빈도 | 재시작 때 번호 빈 곳이 커짐 (문제없음) |
| B | 주문, 주문 상품만 100 | 고빈도 대상이 최소 | 할인 배분과 상태 이력은 주문 상품보다 행이 많아, 몰릴 때 오히려 이쪽이 병목이 됨 |
| C | 모두 20 | 규칙이 하나 | 발매처럼 주문이 몰릴 때 시퀀스에서 기다림이 생김 |

**추천: A.**
- 행이 가장 많이 생기는 쪽은 주문보다 상태 이력과 할인 배분입니다. 주문 하나를 만들 때 이 테이블들에도 여러 행이 한꺼번에 들어갑니다.
- 장바구니는 주문보다 훨씬 자주 담고 지웁니다.

**A를 고르면 생기는 것**
- 시퀀스 6개 (CACHE 100 다섯 개, 20 하나)

<!--ANSWER-->
**사용자:** a

10-4는 A로 메모했습니다.
