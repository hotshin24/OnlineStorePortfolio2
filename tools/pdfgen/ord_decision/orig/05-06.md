## 5-6. 배송 요청 사항

**무엇을 정하나요?**
"문 앞에 놓아 주세요", "부재 시 경비실" 같은 **배송 요청을 주문에 어떤 형태로 남길지**입니다. 5-5 A에 따라 위치는 주문 테이블입니다. 여기서는 형태만 정합니다.

**회원 도메인은 어떻게 했나요?**
회원 배송지(`MBR_DELIVERY_ADDRESS`)에는 이미 세 컬럼이 있습니다.
- **수령 장소 코드** (`DELIVERY_PLACE_CD`): 문 앞, 경비실, 택배함 등. 값 목록과 CHECK가 있습니다.
- **배송 요청 사항 암호문** (`DELIVERY_REQUEST_ENC`): 고객이 직접 쓰는 문구
- **공동현관 출입 방법 암호문** (`ENTRANCE_ACCESS_ENC`): 5-8에서 따로 다룸

배송 요청 문구를 암호화한 이유는 고객이 "현관 비밀번호 1234#" 같은 민감한 내용을 적는 경우가 많기 때문입니다.

**예시로 보면**
- 수령 장소: 문 앞
- 요청 문구: "아기가 자고 있어요. 벨 누르지 마세요."

고객이 회원 배송지를 골라 주문하면 이 값들이 주문으로 복사됩니다. 주문서에서 이번 주문만 다르게 바꿀 수도 있습니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 회원 배송지와 같은 형태로 둠: 수령 장소 코드 + 요청 문구 암호문 | 회원 배송지에서 그대로 복사됨. 코드는 택배사 연동과 통계에 씀. 민감한 문구가 보호됨 | 문구를 볼 때 복호화가 필요함 |
| B | 수령 장소 코드 + 요청 문구 평문 | 복호화가 없음 | 회원 배송지에서는 암호화했던 문구가 주문에서 평문이 됨. 같은 값의 보호 수준이 달라짐 |
| C | 요청 문구 평문만 둠 (코드 없음) | 가장 단순함 | 택배사에 넘길 표준 값이 없음. 회원 배송지 구조와 다름 |

**추천: A.**
- 같은 값이 회원 배송지에서는 암호문이고 주문에서는 평문이면, 주문 테이블이 약한 고리가 됩니다.
- 수령 장소 코드는 회원 도메인의 코드 그룹을 함께 씁니다. 새 코드 그룹이 생기지 않습니다.
- 출고할 때 창고·배송 도메인이 복호화해 택배사에 넘깁니다. 배송이 끝난 뒤 요청 문구를 언제 지울지는 5-8(공동현관 파기 시점)과 함께 정할 수 있습니다.

**A를 고르면 주문 테이블에 생기는 것**
- 수령 장소 코드 (CHECK: 값 목록)
- 배송 요청 사항 암호문 (`_ENC`, 회원과 같은 길이)
