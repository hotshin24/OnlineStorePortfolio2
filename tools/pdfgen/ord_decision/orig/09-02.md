## 9-2. 비회원 주문의 회원 연결 기록

**무엇을 정하나요?**
비회원으로 했던 주문을 나중에 **회원 계정에 연결할 때 무엇을 남길지**입니다.

**이미 정한 것**
선행 14 [확정]: 비회원 주문 후 회원 가입을 유도하고, 과거 비회원 주문은 **휴대폰 해시로 회원에 연결**합니다. 비회원 주문의 회원 ID는 처음에 NULL입니다.

**예시로 보면**
1. 3월에 비회원으로 셔츠를 샀습니다 (휴대폰 010-1234-5678).
2. 6월에 같은 번호로 회원 가입하고 본인인증을 합니다.
3. 시스템이 "이 번호로 한 비회원 주문 1건이 있습니다. 내 주문으로 가져올까요?"라고 묻고, 고객이 수락합니다.
4. 주문의 회원 ID가 채워지고, 마이페이지에 3월 주문이 보입니다.

**조심할 점**
휴대폰 번호는 다른 사람에게 다시 배정될 수 있습니다. 예전 번호 주인이 한 비회원 주문이 새 번호 주인 계정에 붙으면 남의 주문 내역(주소, 상품)이 보입니다.

**선택지**

| 선택지 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | 연결하면 주문의 회원 ID를 채우고, 연결 일시와 연결 방식 코드(가입 때 자동 제안 수락, 고객센터 요청 등)를 남김. 연결 조건: 회원이 본인인증을 마쳤고, 휴대폰 해시가 같고, 주문의 본인인증 일시(9-1 A)가 회원의 그 번호 인증 시점과 겹치지 않는 범위 확인 | 원래 비회원 주문이었다는 사실이 남음. 언제 어떻게 연결했는지 추적됨 | 컬럼 2개 |
| B | 연결 이력 테이블을 둠 (연결·해제 한 번 = 한 행) | 잘못 연결해 해제한 기록까지 남음 | 테이블 1개. 해제는 드묾 |
| C | 회원 ID만 채움 | 단순함 | 원래 비회원 주문이었는지, 언제 연결했는지 알 수 없음 |

**추천: A.**
- 잘못 연결을 막는 핵심은 "본인인증한 번호"끼리만 맞추는 것입니다. 비회원 주문도 본인인증을 했고(9-1 A), 회원도 본인인증을 했으므로, 두 인증이 같은 사람이라는 근거가 됩니다.
- 그래도 번호 재배정 위험이 남으므로, 연결은 자동으로 하지 않고 고객이 목록을 보고 수락하게 합니다.
- 연결한 뒤에도 비회원 비밀번호 해시와 주문자 스냅샷(5-5 A)은 그대로 둡니다. 주문 당시의 기록이기 때문입니다.
- 잘못 연결해 되돌리는 일은 드뭅니다. 되돌리면 회원 ID를 다시 NULL로 바꾸고 연결 값을 지웁니다. 그 기록은 데이터 변경 감사 로그에 남습니다.

**A를 고르면 주문 테이블에 생기는 것**
- 회원 연결 일시, 회원 연결 방식 코드 (새 코드 그룹, CHECK)
- CHECK: 연결 일시가 있으면 회원 ID와 본인인증 값(9-1)이 NOT NULL
